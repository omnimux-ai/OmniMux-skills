# AI 换装

AI 换装的内部价值，不是直接替人出图，而是把人物保持、服装还原、场景目标和风险边界整理清楚，方便后续人工判断、提示设计和结果复核。

## 包定位

- 只保留静态审阅材料：方法说明、提示、schema、样例和静态配置。
- 适合内部分析、方案整理、质检对照和交付前复核。
- 不把来源记录、脚本、工作流、适配器或采集残留暴露为 skill 正文。

## 适用场景

- 用户已提供人物图和服装图，需要先整理换装方案与风险边界。
- 需要为电商主图、详情页、社媒内容或广告素材做换装提示草案。
- 需要在多人、多服装、多场景任务里先统一输入结构和质检标准。
- 需要审阅“哪些细节必须保留、哪些地方允许合理补全”。

## 不适用场景

- 未经授权的人物换装、身份伪造、羞辱性编辑或误导性试穿证明。
- 只要最终成图、却没有任何人物/服装约束信息的请求。
- 依赖脚本、工作流、适配器或外部服务才能体现核心价值的执行型能力。
- 试图把分析任务升级成固定工具顺序、固定阶段机或隐藏执行流程。

## 输入要求

- 人物图、服装图，或最少的文字约束。
- 明确输出用途：电商展示、社媒内容、广告测试、内部提案等。
- 明确保留项：脸、发型、体态、姿势、背景、服装关键细节。
- 明确风险项：授权状态、品牌元素、职业身份、夸大效果、敏感身体编辑。

## 任务模式

| 模式 | 用途 |
| --- | --- |
| `intake` | 收拢人物、服装、用途、保留项和风险项。 |
| `single_tryon_plan` | 整理单次换装的提示草案、假设和质检要点。 |
| `variant_plan` | 规划多模特、多场景、多角度或多颜色变体。 |
| `qa_review` | 复核身份一致、服装结构、商业真实性和交付风险。 |

## 输出合同

- 输入素材摘要和缺失信息。
- 换装目标描述与关键保留约束。
- 可执行的提示草案、负向约束和质检项。
- 风险结论：可继续、需确认、应拒绝。
- 需要人工复核的点，例如品牌元素、真实性表达、授权证明。

## 运行边界

- 本 skill 只提供任务理解与审阅依据，不新增代码执行能力。
- 不强制工具调用顺序、固定阶段机、required-next tool 或隐藏 workflow owner。
- 如果缺少关键信息，只补最小必要澄清；其余部分明确假设即可。
- 如果未来核心价值必须依赖脚本、工作流或适配器，应改按代码执行候选能力单独治理，而不是进入公开业务 skill。

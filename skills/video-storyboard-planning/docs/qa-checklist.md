# QA Checklist

## 目的

本文件用于对“视频分镜图 skill”的输出结果进行质量检查，确保最终交付物不是“写得像分镜”，而是真正满足以下要求：

- 结构完整
- 平台适配
- 卖点清楚
- 镜头可执行
- 可用于 AI 生成 / 真人拍摄 / 剪辑协作
- 适合商业短视频目标

本清单既可用于人工审稿，也可用于自检或流程化验收。

---

## 使用方式

建议在输出完成后，按以下顺序检查：

1. 先看项目层是否清楚
2. 再看结构层是否合理
3. 再看镜头层是否具体
4. 再看执行层是否能落地
5. 最后看文件间是否一致

可按以下方式使用：
- 逐项打勾
- 标记风险等级
- 写修订意见
- 作为 review 模板复用

---

## 一、项目层检查

### 1. 视频目标是否明确
- [ ] 是否能用一句话说清这条视频的主要目标
- [ ] 是否明确是为了点击、下单、种草、认知还是展示
- [ ] 是否没有把多个冲突目标混在一起

### 2. 目标受众是否清楚
- [ ] 是否知道视频主要是给谁看的
- [ ] 是否能看出受众痛点或动机
- [ ] 分镜内容是否与受众生活场景匹配

### 3. 平台与时长是否明确
- [ ] 是否明确平台（如 TikTok）
- [ ] 是否明确画幅（如 9:16）
- [ ] 是否明确时长范围（如 15s / 30s）
- [ ] 镜头密度是否与时长相符

### 4. 风格是否可执行
- [ ] 风格描述是否足够具体
- [ ] 是否不是只有“高级感”“质感好”这类抽象词
- [ ] 风格是否与视频目标相匹配

---

## 二、结构层检查

### 5. 是否有清晰的视频结构
- [ ] 是否有开场
- [ ] 是否有中段价值展示
- [ ] 是否有结尾收口
- [ ] 结构是否符合用户理解路径

### 6. 前 3 秒是否有效
- [ ] 开场是否有明确 Hook
- [ ] 是否能快速建立问题、代入或结果预期
- [ ] 是否避免了慢热、无信息开场

### 7. 镜头顺序是否合理
- [ ] 产品出现时机是否合理
- [ ] 卖点顺序是否符合理解逻辑
- [ ] CTA 是否在价值建立后自然出现
- [ ] 是否没有跳跃式、无理由的段落切换

### 8. 信息密度是否合理
- [ ] 是否没有在短时间内堆太多卖点
- [ ] 是否没有出现大量重复镜头任务
- [ ] 是否没有长段空镜或低信息镜头

---

## 三、镜头层检查

### 9. 每个镜头是否有明确任务
- [ ] 每个镜头是否能说清“这一镜负责什么”
- [ ] 是否避免一个镜头承担太多任务
- [ ] 是否没有“好看但没用”的镜头

### 10. 画面是否具体
- [ ] 是否能明确看出主体是谁/是什么
- [ ] 是否能明确看出动作是什么
- [ ] 是否能明确看出场景在哪里
- [ ] 是否能明确想象镜头内容

### 11. 卖点是否被可视化
- [ ] 核心卖点是否通过画面而不是只靠文案表达
- [ ] 是否有具体动作/场景支撑卖点
- [ ] 是否避免空泛表达如“高级、方便、好用”但无画面证明

### 12. 景别与运镜是否合理
- [ ] 景别是否服务镜头任务
- [ ] 运镜是否必要且易执行
- [ ] 是否没有为了“酷”而加无意义运镜
- [ ] 是否适合短视频观看节奏

### 13. 时长分配是否合理
- [ ] 每个镜头时长是否可行
- [ ] 是否没有镜头过短以致无法理解
- [ ] 是否没有镜头过长导致拖沓
- [ ] 前中后段节奏是否协调

---

## 四、文案与画面配合检查

### 14. 口播、字幕、画面是否互补
- [ ] 画面、口播、字幕是否不是完全重复
- [ ] 画面是否承担展示任务
- [ ] 口播是否承担解释或增强任务
- [ ] 字幕是否承担提炼和强调任务

### 15. 文案是否口语化、适配平台
- [ ] 是否符合短视频语言习惯
- [ ] 是否没有过度书面化表达
- [ ] 如果是 UGC，是否像真人会说的话
- [ ] 如果是带货，是否足够直接但不过硬

### 16. CTA 是否自然有效
- [ ] CTA 是否明确
- [ ] CTA 是否不突兀
- [ ] 是否与前文价值逻辑衔接
- [ ] 画面是否支持 CTA 落地

---

## 五、执行层检查

### 17. 是否可用于 AI 出图
- [ ] 每个镜头是否足够具体到能写 prompt
- [ ] 产品外观是否清楚
- [ ] 人物/场景是否有一致性基础
- [ ] 是否避免纯抽象描述

### 18. 是否可用于 AI 视频
- [ ] 动作是否明确
- [ ] 镜头切换是否清楚
- [ ] 多镜头之间是否有连续性
- [ ] 是否便于进一步改写成镜头级视频 prompt

### 19. 是否可用于真人拍摄
- [ ] 镜头是否能拍出来
- [ ] 场景是否现实可搭
- [ ] 人物动作是否自然
- [ ] 是否没有依赖不现实的复杂效果
- [ ] 拍摄备注是否足够支撑执行

### 20. 是否可用于后期剪辑
- [ ] 是否有清楚的镜头边界
- [ ] 是否有合理节奏点
- [ ] 是否便于安排字幕
- [ ] 是否可以自然做转场和信息衔接

---

## 六、一致性检查

### 21. 产品一致性
- [ ] 产品名称是否一致
- [ ] 产品颜色/外观是否一致
- [ ] 产品功能表达是否一致
- [ ] 不同文件之间是否没有矛盾

### 22. 人物一致性
- [ ] 人物设定是否统一
- [ ] 场景切换中人物身份是否稳定
- [ ] 表达方式是否一致
- [ ] 是否没有一会儿像广告模特、一会儿像素人但无说明

### 23. 场景一致性
- [ ] 场景切换是否有理由
- [ ] 不同场景是否都服务卖点
- [ ] 是否没有无意义跳场
- [ ] 是否符合整体风格统一

### 24. 风格一致性
- [ ] 视频整体语气是否统一
- [ ] 分镜与 prompt 是否风格一致
- [ ] 视觉方向是否稳定
- [ ] 没有前半段 UGC、后半段突然大片化而无设计理由

---

## 七、文件级检查

### 25. `storyboard.md` 是否完整
- [ ] 是否包含项目摘要
- [ ] 是否包含结构总览
- [ ] 是否包含逐镜头设计
- [ ] 是否包含节奏或执行建议

### 26. `shotlist.csv` 是否规范
- [ ] 字段是否完整
- [ ] 时间是否连续合理
- [ ] 每个镜头是否能独立理解
- [ ] 是否与 storyboard 一一对应

### 27. `prompts.md` 是否可用
- [ ] 是否有统一风格约束
- [ ] 是否有负面提示词
- [ ] 是否有镜头级 prompt
- [ ] 是否有一致性说明
- [ ] prompt 是否不是单纯风格词堆砌

### 28. 其他文件是否互相一致
- [ ] `storyboard.md` 与 `shotlist.csv` 是否一致
- [ ] `storyboard.md` 与 `prompts.md` 是否一致
- [ ] CTA、卖点、人物、产品、场景是否一致
- [ ] 是否没有文件之间的信息冲突

---

## 八、商业目标检查

### 29. 是否体现商业价值
- [ ] 是否能看出为什么用户会继续看
- [ ] 是否能看出为什么用户会感兴趣
- [ ] 是否能看出为什么用户会相信
- [ ] 是否能看出为什么用户会行动

### 30. 是否符合短视频电商逻辑
- [ ] 是否有明确的停留设计
- [ ] 是否有明确的卖点映射
- [ ] 是否有信任或结果层
- [ ] 是否有明确行动引导

---

## 九、常见问题红旗

如果出现以下任一情况，应视为需要返工：

- [ ] 只有创意概述，没有逐镜头内容
- [ ] 只有文案，没有画面说明
- [ ] 画面描述过于抽象，无法生成或拍摄
- [ ] 前 3 秒没有有效 Hook
- [ ] CTA 生硬或缺失
- [ ] 多个镜头承担重复任务
- [ ] 产品卖点没有被可视化
- [ ] 文件之间相互矛盾
- [ ] 风格不统一
- [ ] 项目目标不明确

| 维度 | 分数（1-5） |
|---|---|
| 目标清晰度 |   |
| 平台适配度 |   |
| Hook 强度 |   |
| 卖点可视化 |   |
| 镜头执行性 |   |
| 节奏合理性 |   |
| 一致性控制 |   |
| CTA 有效性 |   |
| AI 生成适配 |   |
| 拍摄协作适配 |   |

### 评分参考
- 5 分：非常清楚，可直接执行
- 4 分：整体可用，小幅修改即可
- 3 分：基本可用，但存在明显问题
- 2 分：问题较多，需要较大调整
- 1 分：不具备执行价值

---

## 一句话总结

这份 QA 清单的核心不是检查“写了多少”，
而是检查：

**这份分镜能不能真的拿去做内容。**

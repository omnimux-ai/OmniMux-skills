# Skill-Teaching Course Detail Page Design Assistant

Use this workflow when a user needs to design an e-commerce detail page for a skill-teaching course.

**What is a skill-teaching course?** At its core, it's about "teaching users to master a skill to solve real-world problems" — exam score improvement, coding & development, design software, writing & communication, finance & investing, fitness & weight loss, photography & retouching, musical instruments, language learning, workplace communication, etc.

**How it differs from the general detail page:** The general skill uses an "emotional → rational" three-part structure (Hook → Empathy → Evidence), suitable for SaaS/memberships/consulting and other broad categories. This skill uses a 6-layer persuasion funnel designed specifically for skill teaching — users don't just need to be moved emotionally, they need to understand "how I can master skills and solve problems in real scenarios through this course."

---

## Core Design Principles

### Principle 1: 6-Layer Persuasion Funnel

The order must not be shuffled. Each layer addresses a specific question in the user's mind:

| Layer | Page | User's Question | Core Function |
|-------|------|----------------|---------------|
| L1 | Hero Highlights Page | "What course is this? Is it relevant to me?" | Grab attention in 1 second: course name + core highlights + visual impact |
| L2 | Scenario Pain Points Page | "Yes, that's exactly me!" | Build empathy: specific problems in real scenarios |
| L3 | Solutions Page | "How does this course help me solve it?" | Methodology layer: unique methods/systems/frameworks |
| L4 | Curriculum Page | "What exactly will I learn? How long?" | Execution layer: lessons/modules/learning path |
| L5 | Instructor & Results Page | "Is the instructor reliable? Does it actually work?" | Trust layer: credentials + results + student outcomes |
| L6 | Service Guarantee Page | "What additional value is there?" | Final push: community/Q&A/materials/after-sales |

**Why this order works:** L1-L2 emotional activation ("this is about me") → L3-L4 rational persuasion ("how it helps me") → L5-L6 trust closure ("is it reliable")

**Common ordering mistakes:**
- ❌ Curriculum before pain points → Users don't know why they should learn; they'll swipe away after seeing the syllabus
- ❌ Instructor intro before method → Users don't care who the teacher is; they care "what can you help me solve"
- ❌ Pain points and solutions mixed together → Can't feel the clear "problem → solution" path
- ❌ Pain points without scenarios → "Getting multiple-choice wrong" is weaker than "always picking the wrong one in a 50/50 on the exam"

### Principle 2: Scenario > Pain Point > Feature

The persuasive power of skill teaching comes from scenario immersion, not listing features.

| Level | Weak Copy | Strong Copy |
|-------|-----------|-------------|
| Scenario | "Struggling with learning" | "On the exam, when it's down to two choices, you always pick the wrong one" |
| Pain Point | "Low accuracy on multiple choice" | "You reviewed three times, but your mock test scores actually went down" |
| Solution | "Teaching you problem-solving methods" | "Deconstruct the test-maker's underlying logic — go from guessing right to knowing why" |

**Three-question self-check:** (1) Can users see themselves in this sentence? (2) Will they think "yes, that's exactly it"? (3) Can they imagine being stronger after completing the course?

### Principle 3: Solution-Curriculum Two-Layer Progression

L3 (Solutions) and L4 (Curriculum) are different layers and must not be conflated:

| | L3 Solutions Page | L4 Curriculum Page |
|---|---|---|
| Answers | "What method helps you?" | "What exactly will you learn?" |
| Granularity | Methodology/system/framework (abstract) | Modules/lessons/knowledge points (concrete) |
| Example | "Logic-Based Problem Solving" | "Lesson 1: Logic-Based Problem Solving for Multiple Choice (Part 1)" |
| User Feeling | "The method sounds solid" | "With this arrangement, I can actually learn it" |

**Iron rule:** L3 explains "why this method works," L4 explains "how to execute this method specifically."

### Principle 4: Instructor & Results Evidence Chain

L5 builds a complete trust evidence chain, with each link addressing a deeper layer of doubt:

Instructor credentials (why qualified to teach) → Teaching method differentiators (how it differs from others) → Teaching results data (how students performed) → Student testimonials (what real people say)

- Data > Adjectives ("Validated by 1M+ students" > "Widely praised")
- Specific > Vague ("Multiple-choice accuracy improved by 23%" > "Scores improved significantly")
- Third-party endorsement > Self-proclamation

### Principle 5: 5-Level Noise Reduction for Text-Heavy Content

Skill course copy is typically lengthy. Strictly apply 5 hierarchy levels so users can "scan" and grab key points:

| Level | Function | Font Size Ratio | Font Weight |
|-------|----------|----------------|-------------|
| L1 Main Title | Core selling point | 100% (largest) | Bold |
| L2 Section Title | Section navigation | ~60% | Bold |
| L3 Keywords | Emphasis | ~40% | Medium |
| L4 Body Text | Detailed description | ~35% | Regular |
| L5 Auxiliary Notes | Annotations & fine print | ~25% | Light |

Adjacent levels must differ by ≥ 30% in font size.

### Principle 6: Making Intangible Skills Tangible — Four Visualization Techniques

Skills are invisible and intangible. Use visual methods to concretize learning outcomes:

1. **Path Visualization**: Step diagrams/pathway charts/timelines — show the growth trajectory from "can't do it" to "mastered it"
2. **Before/After Comparison**: Before/After — capability difference before vs. after learning
3. **Method Visualization**: Flowcharts/framework diagrams/mind maps — turn methodology into a perceivable structure
4. **Data Anchors**: Specific numbers (class hours/score improvement/pass rate/student count) — replace adjectives with data

Each detail page set should use at least 2 of these techniques.

## STEP 0: Gather Course Information

Collect the following from the user (don't re-ask what's already known):

### Required Information
1. **Course Name**: Official name and subtitle
2. **What Skill Is Taught**: What capability does this course help users master
3. **Target Users**: Who will enroll (identity + current skill level)
4. **Scenario Pain Points**: What specific problems users face in what real scenarios (the more specific, the better)
5. **Solutions**: What unique methods/systems the course uses to solve these problems
6. **Course Content**: How many lessons, how many modules, what each module covers
7. **Instructor Introduction**: Credentials, teaching style, signature achievements

### Optional Information
1. Student outcome data: score improvement/pass rate/employment rate and other specific numbers
2. Value-added services: community/Q&A/materials/live sessions, etc.
3. Brand tone: professional & rigorous / young & lively / premium & refined / warm & supportive
4. Brand color: specific hex values if any
5. Reference images: competitor examples or preferred style references
6. Dimensions: detail page aspect ratio (default 3:4 portrait)

If the user provides reference images, analyze the design language of the references before starting the plan.

---

## STEP 1: Plan the 6-Layer Persuasion Funnel

Based on the collected course information, plan specific content for each layer.

### L1 Hero Highlights Page (Hook)

Planning elements:
- Visual presentation of the course name (main title + subtitle)
- 3-4 core highlight tags (floating card format)
- Brand endorsement elements (platform/partners/data)
- Core visual (instructor image/IP character/skill-related 3D elements)
- Call-to-action copy

**Highlight extraction principle:** Highlights are not a feature list — they're "one sentence explaining why this course is special." Good highlight = Differentiation + Specificity + Appeal.
- ✅ "Accurately predicted college entrance exam trends for 4 consecutive years"
- ❌ "Expert instructors, comprehensive content"

### L2 Scenario Pain Points Page (Empathy)

Planning elements:
- 2-4 specific pain points in real scenarios
- Each pain point includes scenario immersion (not just "XX is bad," but "encountering what problem under what circumstances")
- Emotional progression of pain points (light to heavy, or common to core)
- One summarizing golden sentence (attributing all pain points to one root cause)

**Scenario copy template:** `[Scenario description], have you also [specific behavior/symptom]?`
- "On the exam, when it's down to two choices, you always pick the wrong one"
- "Coded for 3 hours, spent 2 hours finding the bug"
- "Made 100 design drafts, client says the first version was best"

### L3 Solutions Page (Method)

Planning elements:
- The course's core methodology/teaching system (not specific class sessions — methodology level)
- How each method maps to L2 pain points (creating a one-to-one "pain point → solution" mapping)
- Differentiated expression of methods (the core point of "what I teach is different from others")

**Solution copy template:** `[Pain point] → I use [method name] to help you [achieve result]`
- "Can't nail multiple choice → Logic-Based Problem Solving: go from guessing right to knowing why"
- "Can't find the bug → Systematic 4-Step Debugging: locate the root cause in 30 seconds"

### L4 Curriculum Page (Curriculum)

Planning elements:
- Course overview (number of lessons/modules/total duration)
- Module breakdown and core theme of each module
- Progressive learning path relationships (Fundamentals → Advanced → Practice → Sprint)
- Goal statement for each module (what you can do after completing this module)

**Visual presentation suggestions:** Ascending staircase path diagram (implying skill progression) / Timeline flowchart (implying learning rhythm) / Module card layout (clearly displaying structure)

### L5 Instructor & Results Page (Trust)

Planning elements:
- Instructor's core credentials (1-2 sentences, not a full resume)
- Teaching method differentiators (what makes this instructor different)
- Teaching results data (specific numbers: student count/score improvement/pass rate/employment rate)
- Student testimonials/reviews (if available)

### L6 Service Guarantee Page (Service)

Planning elements:
- Value-added services list (community/Q&A/materials/live sessions/homework review, etc.)
- Specific service descriptions (not just "has a community," but "join the exclusive group upon enrollment, daily curated content shared on schedule")
- Additional target audience notes (if there are extra applicable scenarios)
- Final CTA (call to action)

---

Output the complete 6-layer architecture plan (copy content + visual direction for each layer) and present to the user for confirmation.

## STEP 2: User Confirms Architecture

Present the 6-layer architecture plan to the user. Confirm at this stage:
- Whether the copy content for all 6 layers is accurate
- Whether the scenario pain points are real and immersive
- Whether the Solution → Curriculum progression is clear
- Whether the instructor results data is real and usable
- Whether any layers need to be merged/split (layers with thin content can be merged)

**Flexible merging principle:** The 6 layers are logical layers, not necessarily 6 images.
- Layers with less content can be merged (e.g., L5+L6 merged into one "Instructor & Service" page)
- Layers with heavy content can be split (e.g., L4 curriculum has a lot of content, split into 2 pages)
- Final number of images = user-confirmed count, typically 4-6

Proceed to the generation phase after user confirmation.

## STEP 3: Generate Detail Pages

Generate detail page images according to the user-confirmed architecture.

### Generation Requirements

**Text Rendering:**
- Text is the core — text accuracy is the top priority
- Main titles must be clearly legible with no typos
- Strictly follow the 5-level noise reduction system
- Use font styles appropriate for the brand tone for Chinese text

**6-Layer Logical Coherence:**
- Each image is standalone, but the reading sequence should feel logically progressive
- L2 pain points and L3 solutions must correspond one-to-one
- L3 methodology and L4 curriculum must logically connect
- Visually link everything with a consistent color scheme and design language

**Visual Style:**
- Maintain visual consistency across the entire set (same color scheme, same design language, same typography system)
- Apply the "making intangible skills tangible" strategies (path diagram/before-after comparison/method visualization/data anchors — at least 2)
- Modern details (rounded cards, diffused shadows, gradients, decorative elements)
- Background should not be pure white — use an extremely low-saturation variant of the primary color

**Batch Generation Strategy:**
- Generate all detail pages in one batch (or 2 batches) to ensure style consistency
- Every image's prompt includes shared style anchors
- Every image has independent content and layout descriptions

## STEP 4: Present Results + Iterate

Display all generated detail pages, arranged in 6-layer funnel order.

**Checklist (execute internally, do not show to user):**
- Is text clearly legible with no typos
- Is the 5-level font size hierarchy clear
- Is the 6-layer persuasion logic coherent (can users read from L1 through L6 without dropping off)
- Do the scenario pain points feel immersive
- Is the Solution → Curriculum progression clear
- Is the instructor results trust chain complete
- Is color/style consistent across the entire set
- Are the "making intangible skills tangible" elements in place

If issues are found, identify the specific cause and selectively regenerate.

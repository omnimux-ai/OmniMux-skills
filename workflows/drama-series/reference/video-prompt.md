# 视频片段 Prompt 参考

> 在 `visual-gen` 阶段编写或修订非 MiniMax H3 视频 clip work item 的 `prompt` 字段时读取。MiniMax H3 使用完整独立的 `h3-video-prompt.md`，不读取或拼接本文骨架。

## 模型选择与公共编译边界

- Planner 在当前 Visual Gen authoring turn 必须实际读取 `storyboard_document_node_id` 和条件性的 `blocking_memory_document_node_id` 所指向的分镜、站位原文，再结合资产锚点和有序 `refs` 填入下方骨架；只读取 Plan JSON、`execution_excerpt`、阶段摘要或此前上下文不算完成来源读取。Executor 只按 work item 原样派发 Prompt 和 `refs`。
- 先读取 `execution_locks.vendor_model_policy`。仅当 `{vendor: MiniMax, model_id: MiniMax H3}` 完整匹配时，改读同目录完整独立的 `h3-video-prompt.md`；其他模型逐字使用本文下方骨架。模型锁缺失或不完整时阻塞，不得猜测模板或模型。
- 骨架中除 `{{...}}` 外的首段、章节标题、标点和顺序全部是必须逐字保留的固定文字，不得改写、缩写或追加同义句。`{{...}}` 是整块待替换变量，最终 Prompt 中不得留下双花括号、变量名、填写说明、检查项或示例句。
- 每个镜头组重新从已确认来源编译；会话摘要、上一条 Prompt、失败重试摘要和宫格图都不能替代分镜与站位事实。
- 完整效果优先于规划速度、token、payload 和批量效率。不得把逐镜叙事压成剧情摘要，也不得用空间说明或摄影术语堆字数。
- 最终输出是一段连续的全画幅音视频；宫格只提供本组构图、景别、动作和顺序参考。

## 参考图逐槽绑定

1. 编写 `refs` 前，先从本 `clip_group_id` 的分镜行、站位起始/末态和场景/道具状态建立 required asset roster：列出所有具名可见角色（含在场但沉默的旁观者）、当前可复用场景和可见核心道具。同场景连续组以上一组完整在场名单为起点，只移除来源明确离场的角色，只加入来源明确入场的角色。
2. 以完整 `asset-anchors.runtime.runtime_refs` 为可用资产事实表，并结合对应 `ref_capsules` 匹配身份和当前状态。不得把当前 `asset-anchors.work_items`、`retry_ids`、本轮局部修订清单或宫格 `refs` 当成完整资产表；它们都不能证明其他既有资产不存在。
3. 对 required asset roster 逐项匹配：完整 runtime refs 中已有对应角色当前状态卡、场景卡或道具卡时，必须加入本组 `refs`，不得降级成文字描述。只有完整 runtime refs 确实没有可用匹配时，才以具体名称、外观/空间、位置和作用写成文字，不编造图号。
4. `work_items[].refs` 是实际派单顺序：风格参考（仅需要时）→ 本组在场角色的当前状态卡 → 场景卡 → 可见核心道具卡 → 本组宫格（仅启用时，固定最后一张）。
5. Reference roster 与 `refs` 数量、顺序一一相等，每张图独占一行：`图N = <角色/场景/道具名称>，锁定<身份、当前状态或空间属性>`。不得把多张资产塞进同一个“图1”，不得用文件名、asset id 或一段总述代替逐图绑定。
6. 使用宫格时，Planner 必须先把对应 `clip_group_id` 的 grid runtime ref 写入 work item `refs` 最后一位，再写最后一条 `图N = 本镜头组宫格，STORYBOARD PLAN ONLY，只参考动作、空间、景别和顺序`。跳过宫格或不在 `keyframe_scope` 时两处都不出现；Executor 不得自行追加、替换或重排宫格。宫格只负责构图参考，不能决定或替代 required asset roster。
7. 正文首次进入角色、切换焦点或重新绑定身份时写“角色名（图N）”。同一角色的互斥状态卡不进入同一组；在场但沉默的角色仍绑定其当前卡并在画面中定位。

## 环境与空间只写起始事实

- 【环境光影】用一至两句写本组时段、基础光源方向/色温和本组真实光影变化；不复述剧情、人物站位、每层布景或抽象“戏剧功能”。
- 【空间基准】用紧凑自然语言写具体场景和锚物、全部在场角色的起始位置/面向/视线、核心道具状态和默认机位侧。只写模型还原本组起始画面必需的事实；人物移动、受击、表情变化、镜头落点和末态全部写进【画面演进】。
- 把“主锚”、坐标和表格字段翻译成可见物件与相对位置；同场景连续组从上一组末态复制事实，但仍写出具体角色、锚物和状态，不写“沿用上一组”或“原位”。

## 画面演进：连续叙事优先，镜头随剧情展开

1. 【画面演进】首先要像一段能直接读懂的连续剧情：谁先做什么、镜头如何跟上、焦点落到谁、角色怎样表演和说话、其他人如何反应、画面怎样接到下一步。即使不回看【空间基准】，读者也应能顺畅理解本段动作、人物关系、台词和情绪变化。
2. 分镜列表每一行对应一个独立自然段，顺序和 `source.shot_count` 一致；不用“镜头段 1”“填写……”等内部标签，也不按固定检查清单逐项报字段。每段从上一段可见末态自然起笔，按实际发生顺序把动作、镜头、表演、台词、背景、反应和声音组织成连续 prose。
3. 空间事实只在理解当前画面、人物移动或正反打背景时自然带出，不重复整段站位表。镜头切换后要让读者知道画面现在打到谁、他身后是什么、其他在场人物处于什么关系，但不能让空间说明盖过剧情。
4. 镜头运动由 LLM 根据当前分镜的动作强度、视线变化和情绪节拍选择。写清镜头从哪里开始，以跟移、横摇、快速甩切、推进、后拉、升降或短促震动中的合适方式跟随什么，最后落在谁的何种景别；焦点落下后，再根据角色的震惊、压迫、犹疑或反转判断是否轻微前推、短暂停稳、后拉或转向反应人物。只选择当前画面真正需要的运动，不把所有运镜同时堆进一段。
5. 突发动作或冲突点要把动作与镜头写在同一时间线上：先写动作如何发生，再写镜头如何随动作改变焦点、在冲击点产生何种画面反馈、最终落到哪位角色或哪个细节；紧接着写落点人物的具体表情和身体反应、逐字台词、听者或旁观者反应以及同步音效。具体运镜和反馈由当前项目内容决定，不预设固定动作或固定构图。
6. 对白镜头要同时写出当前景别与角度、镜头落点、说话人的眼神/呼吸/嘴角/下颌/姿态变化、逐字台词、听者反应和可辨背景。情绪在一句台词内发生变化时，让镜头随变化做有目的的轻推、停稳、转焦或反打，使台词、表演和镜头运动形成同一条连续节奏。
7. 正反打或过肩镜头要明确镜头从谁的左肩或右肩后反打到谁的正面、侧面或三分之二侧脸，前景肩部位于画面哪侧及虚实状态，目标人物保持什么世界位置，目标身后是哪一侧具体场景背景；随后连续写目标的表情、动作、逐字台词、镜头是保持还是轻推/转焦，以及前景人物和旁观者的反应与声音承接。
8. 每句对白逐字复制并注明说话人的语言、音量、音色、语气和情绪变化。无台词镜头只写可见动作与声音；有物理动作时写与动作时点一致的具体音效、方向、距离和空间混响，不用“伴随音效”一类空话。
9. 第二组及之后从上一组动作的下一帧开始，并通过景别跨档、视点转移、正反打或局部特写形成新构图。同场景保持空间与光照；跨空间、闪回、梦境、反转或章节断点才写与来源匹配的声音先行、溶解、渐白、硬切或黑场 cue。
10. 末镜写清最终构图、角色/道具末态及下一片段可承接的动作、视线或声音。非集尾不为“定格感”强行停住动作。

## 声音、风格与执行自检

- 【声音设计】只汇总本段持续环境声、逐镜动作声和空间声场；每个关键动作的声音仍在对应【画面演进】段落中同步出现。
- 非 MiniMax H3 的 `{{LOCKED_FINAL_STYLE_LINE}}` 只能按制作模式逐字替换整行，不得自行扩写：Mode A 真人实拍固定为 `【画面风格】写实真人摄影质感；真实皮肤质感；自然真实的人类面部特征，带有轻微的生理不完美。电影质感画面，大光圈浅景深，背景柔焦虚化。多用特写和过肩反打，少用全景中景。`；Mode B 漫画/动画固定为 `【画面风格】<制作计划已确认的 Medium lock 原文>`，只替换尖括号内容，不混入真人摄影词，也不追加项目发挥句。
- 派单前只做一次自检：所选模型只使用它对应的骨架；最终 Prompt 无 `{{...}}`、模板教学语或内部字段；required asset roster 中每个具备 runtime ref 的角色、场景和核心道具都已进入 `refs`，没有因当前 work items 或宫格清单省略而降级成文字；随后确认 roster 与真实 `refs` 一一对应且宫格只在最后；【环境光影】和【空间基准】没有挤占剧情；【画面演进】能从头到尾读通，段落数等于 `source.shot_count`，动作、镜头运动、表演、背景、逐字台词、反应、声音和末态按剧情自然连在一起，正反打与转场写清具体画面。非 MiniMax H3 必须逐字匹配本文件固定首段和模式对应的末尾【画面风格】行；MiniMax H3 按 `h3-video-prompt.md` 校验。任一项失败就先重编译该 work item，不进入提示词确认或调用 `hub_generate_video`。
- 网络、超时以及 plan validation 报出的重复 id、缺少 source range、锁项或其他非 Prompt 字段错误，只修改错误明确点名的字段；重试输入中的原 Prompt、原 `refs`、顺序和【画面演进】段落数量必须逐字复用，不得重排、合段、概括或重新编译。只有用户明确修改画面或上游分镜/站位发生变化时才重新编译受影响镜头组。

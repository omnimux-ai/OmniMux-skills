# MG Voiceover Animation Generator Skill

Use this Skill when the user provides product or packaging images, App/SaaS screenshots, a voiceover script or audio, product materials, a real product, a fictional brand or concept-product brief, or only a theme, and wants an MG animation for an explainer, launch, demo, explanation, or abstract topic.

This Skill does not impose a default visual style or treat styles as a mutually exclusive menu. Infer one primary style direction, up to two supporting visual modules, and one core narrative structure from the user's input, reference images, voiceover semantics, and the knowledge base. Ask the user to choose only when several directions are all valid, produce substantially different results, and no preference is clear.

Composable style modules include:

- **Premium product launch / product interface demo**: for AI tablets, phones, headphones, smart hardware, apps, SaaS, AI tools, in-car systems, and wearables. Emphasizes hero-product presentation, interface demos, workflow progression, and brand closure.
- **Clean MG product explainer / information visualization**: for appliances, household products, services, data explanations, courses, tools, and feature benefits. Uses abstract anchors, information cards, graphic metaphors, and continuous bridges.
- **UI / SaaS feature-demo module**: for input fields, dashboards, Bento grids, button clicks, status feedback, multi-device sync, and AI processing flows.
- **Lifestyle appliance-explanation module**: for home settings and everyday expressions of comfort, air, water, temperature, and energy saving.
- **Data / progress / efficiency visualization module**: for big numbers, progress bars, KPI cards, efficiency gains, completion checks, and trend changes.
- **Fictional concept-product launch module**: for user-defined product names or original brands. May create original product exteriors, original UI, and a brand end card, but must not impersonate a real brand.

Product images and voiceover are not always required. When voiceover is missing, ask whether the user wants on-screen copy, voiceover, or both. This Skill follows a “write the H3 prompt and place it on the canvas for approval, then generate after confirmation” workflow; it does not use the old “static storyboard images → multiple MG clips → compositing” production chain.

## Global Naming Rules

- Dynamic imagery generated by H3 is called “MG animation” throughout this Skill.
- The final deliverable is called “final MG animation” or “MG Voiceover Animation Generator output.”
- The complete text written for H3 is called an “H3 prompt document” or “MG animation prompt.”
- Use the word “video” only when referring to an underlying tool, file format, user-uploaded material, or an output outside this Skill.

## Workflow

1. Identify the inputs: product images, real brand, fictional brand or concept product, App/SaaS screenshots, voiceover script, voiceover audio, product materials, or a pure theme.
2. Resolve key decisions: when voiceover is missing, ask whether to write on-screen copy and whether voiceover is needed; when a real product must remain faithful but no product image is available, request one; when a concept product is requested, confirm whether original product appearance and branding are allowed.
3. Combine style and structure: infer one primary style, zero to two supporting modules, and one core narrative structure. Do not force a four-choice style menu or hard-code a fixed process.
4. Analyze materials and copy: extract voiceover meaning, selling points, on-screen keywords, duration structure, product appearance, colors, materials, logo, interface, and elements that must remain faithful.
5. Read the knowledge base and write the H3 prompt: use references as the source of truth and pull in delivery specs, product setup, overall visual style, core structure, timed shots, text motion, element motion, transitions, voiceover, and audio guidance as needed.
6. Place the complete H3 prompt in a Markdown document on the canvas for user review or revision.
7. Do not generate before approval. When the user requests changes, update the canvas prompt document first and wait for confirmation again.
8. After explicit confirmation, use H3 to generate one complete, continuous MG animation.

## Input Rules

1. **Reference image + voiceover**: analyze both and create a faithful, voiceover-driven H3 prompt document, then place it on the canvas for approval.
2. **Reference image without voiceover**: first ask whether to write on-screen copy and whether voiceover is needed; after confirmation, write the prompt document and place it on the canvas.
3. **Voiceover without reference image**: create an information-explainer, feature-explanation, interface-demo, or abstract-theme H3 prompt document based on the voiceover, then place it on the canvas.
4. **Neither reference image nor voiceover**: first ask whether to write on-screen copy and whether voiceover is needed; when necessary also ask about the subject direction, target duration, aspect ratio, style, and whether a fictional brand or appearance is allowed.

Processing rules:

- When both script and audio are available, use audio as the timing baseline and copy as the semantic reference.
- With audio only, transcribe it first and then analyze the meaning.
- With copy only, estimate duration from the copy and plan the timeline in seconds.
- With reference images, preserve appearance, color, material, proportions, logo, structure, and key identifying elements.
- Without a product image, use abstract theme symbols, information cards, UI/graphic containers, and visual metaphors. If the user allows a concept product, an original product appearance may be created.

## Brand and Product Authenticity Rules

- **Real brand / real object / user-uploaded reference**: preserve appearance, color, material, proportions, logo, structure, system interface, and key identifying elements. Do not invent logos, models, package copy, system interfaces, or official brand assets.
- **Fictional brand / concept object / user-defined name**: when the user explicitly provides a fictional name, concept brief, or original-object brief, create original appearance, interface, and brand end card around it. Do not include a real brand logo, real system interface, or real trademark.
- **Category only, with no brand or reference image**: use abstract silhouettes, generic UI, information cards, and graphic metaphors. Do not generate a real brand logo, specific model, or package copy.
- **Continuity of the central object**: when a reference image or concept object exists, keep it as the visual anchor throughout the piece and return to it or a theme card at both the opening and closing.

## Style Combination Rules

- Do not treat styles as mutually exclusive. Choose one primary style direction, zero to two supporting modules, and one core narrative structure.
- The primary style sets the overall atmosphere, background, product presentation, and rhythm. Supporting modules contribute local visual methods and must not make the piece feel stylistically scattered.
- Derive style descriptions from the user's input and semantics. Focus on atmosphere, space, hierarchy, material, visual carrier, and narrative cadence. Do not assume a default style or force a specific color palette.
- Common combinations:
  - AI tablet: premium product launch as the primary style, with UI/SaaS demo and data-efficiency visualization.
  - Smart air conditioner: lifestyle appliance explanation as the primary style, with clean MG explanation and temperature-control UI.
  - AI scheduling app: UI/SaaS feature demo as the primary style, with clean MG and data/progress visualization.
  - Fictional smart hardware: fictional concept-product launch as the primary style, with premium technology launch and UI demo.
- Do not interrupt the user merely to fill out a menu. If the user already specifies a direction such as dark premium tech, clean lifestyle, UI demonstration, or comfortable home appliance, use that combination directly.
- Ask only when multiple directions are equally valid and their visual results would differ substantially.

## H3 Prompt Output Structure

The final prompt written for H3 should prioritize this structure:

1. **Generation specs**: duration, aspect ratio, landscape/portrait, animation type, whether voiceover is included, and whether audio should be generated. Keep a user-specified frame rate if present, but do not rely on frame rate to control the result.
2. **Product setup**: product type, product/brand name, real or fictional status, appearance, core functions, faithful visual elements, and things that must not be invented.
3. **Overall visual style**: background atmosphere, composition, subject lighting, UI style, texture, visual density, and overall feel. Derive these from the input, references, and voiceover semantics without imposing a default palette.
4. **Core structure**: let the knowledge base choose an information flow, comparison, process, central object, timeline, dashboard, or aggregation structure; do not force the same arrow chain every time.
5. **Second-by-second timeline**: for each segment, include visual content, on-screen text, voiceover, element motion, and transition method. Add shot size, camera position, camera movement, subject behavior, background movement, and sound when useful.
6. **Whole-film transitions**: avoid hard cuts and PowerPoint-like switches. Bridge segments with object outlines, screen borders, UI cards, dots, lines, circular progress, keyword glyphs, device connection lines, progress bars, or completion checks.
7. **Text rules**: on-screen text is a design element of the MG/UI/launch film, not ordinary subtitles. Do not create a bottom subtitle bar or display the full voiceover word for word.
8. **Object and brand rules**: preserve real objects; allow original fictional objects without impersonation; with no brand or image, use only abstract objects and generic UI.
9. **Audio guidance**: overall music style, subtle sound effects, and prohibited audio elements.

## Premium Product Launch Structure

When the request is for a premium product film, technology launch, electronic-product interface demo, App/SaaS feature demo, AI product launch, or product hero, prefer:

```text
Hero opening → pain point / use case → AI or core system organizes information → feature interface demo → multi-scene / multi-device linkage → data result or completion state → hero product → brand end card
```

Writing requirements:

- Establish product presence at the opening: reveal from darkness, trace the edge with light, illuminate the screen, then add slight hovering or slow rotation.
- Let UI motion grow naturally from the product screen or the space around the product; do not make unrelated assets float independently.
- Treat each feature section as a workflow step rather than a pile of isolated selling points.
- Return to the product front, product hero, or brand end card at the close.
- When data or a completion state is present, make progress bars, numbers, completion checks, and status dots transform continuously from the preceding UI elements.

## Clean MG Product Explainer Structure

When the request concerns appliances, lifestyle products, service explanations, feature descriptions, data explanations, education, courses, or tools, prefer:

```text
Product/theme setup → pain point or need → core benefit breakdown → scenario experience / workflow demo → data or result proof → brand/theme closure
```

Writing requirements:

- The product may be symbolic or abstract, but the core category must remain stable.
- Use information cards, dots, lines, icons, circular progress, UI panels, and keywords as the primary visual language.
- Put only one core message on each screen and avoid dense small text.
- Plan a bridge between adjacent shots so the result does not look like a PowerPoint.

## Premium Technology Product Launch Style

Suitable for AI tablets, phones, headphones, smart hardware, SaaS, apps, AI tools, in-car systems, and wearables.

Determine the visual direction from the user's input, reference images, and voiceover semantics. Use the knowledge base to choose the background, composition, material, UI, graphics, and rhythm instead of applying a fixed template.

## Product Hero and UI Demo Rules

- When a product image exists, keep the product as the visual anchor and preserve its appearance, color, material, proportions, logo, and key components.
- When no product image exists but the user allows a fictional concept product, create an original product appearance, original UI, and original brand end card.
- The product may emerge from darkness, be outlined by edge light, rotate slowly, illuminate its screen, and unfold its interface at the opening.
- UI motion should grow naturally from the product screen, product edge, device connection lines, or the surrounding space.
- The ending must return to the product front, a product hero frame, a brand name, or a theme closing phrase.
- Product, UI, cards, lines, data, and text must have a clear causal relationship.

## Adjacent-Shot Bridging Rules

- Both premium product films and clean MG explainers must specify a bridge between adjacent segments.
- State clearly what element from the previous segment becomes what element in the next, how long the transition lasts, and how the camera moves.
- Recommended bridges: a cluttered set of cards is attracted into an AI halo and categorized; a feature card stretches rightward into a timeline; timeline nodes fly out to become device connection points; connection lines flow back into the screen and re-form a dashboard; a progress bar contracts into a completion check; the check becomes a light point in the brand end card.
- Do not write only “natural transition,” “smooth switch,” “quick transition,” or “fade in/out.”

## Canvas Prompt-Document Rules

- After generating the H3 prompt, create or update a Markdown document node with `hub_canvas_write_node(kind="text")`. Suggested filename: “product or theme + MG Voiceover Animation Generator Prompt.”
- The document must include a production summary, real/fictional status, input materials, duration, aspect ratio, style, voiceover status, audio-generation status, core structure, and the complete prompt ready for H3.
- Before user approval, do not call `hub_generate_video` or generate the final MG animation.
- When the user requests changes, revise the prompt document first, place the updated version on the canvas, and wait for approval again.
- After explicit approval, use the confirmed prompt from the canvas to call H3 and generate the MG animation.

## Default Audio Guidance

Write restrained, modern, clean low-frequency premium electronic music into the H3 prompt by default. Add very subtle card-slide sounds, AI notification tones, device-connection sounds, completion tones, and a closing sound. No lyrics, noisy voices, heavy beats that overpower the voiceover, or exaggerated cartoon effects. Without voiceover, music and subtle sound effects may carry more of the rhythm while remaining restrained and clean.

## H3 Generation Rules

- By default, use H3 to generate one complete, continuous MG animation, but only after the user approves the H3 prompt document.
- Do not generate static storyboards by default, split the work into multiple clips, or composite multiple clips.
- If the voiceover is too long, first suggest shortening it or ask whether to split it into multiple MG voiceover animations; do not split it without confirmation.
- Do not add ordinary bottom subtitles by default. On-screen text is limited to keywords, short phrases, step labels, data labels, UI labels, product-launch titles, or brand phrases.
- With no voiceover input, first confirm whether the user wants on-screen copy and whether voiceover is needed. Do not write the final H3 prompt document or generate the final MG animation before confirmation.
- Emphasize in the H3 prompt that the result should feel like one complete product MG animation or premium product interface film, not a slideshow of static images.

## Prohibited Actions

- Do not call H3 to generate the final MG animation before the user approves the H3 prompt document.
- Do not skip the canvas approval step for the prompt document.
- Do not use the old “static storyboard approval → multiple MG clips → compositing” chain.
- Do not turn the entire voiceover into bottom subtitles.
- Do not make the result a product-image slideshow or a PowerPoint-like sequence of hard cuts.
- With product images, do not ignore product fidelity. Without product images, do not invent a real brand, real logo, real system interface, or real package copy.
- Do not present a fictional concept product as a real brand product.
- Do not write a vague “premium MG animation” prompt. Include generation specs, product setup, overall style, core structure, second-by-second shots, on-screen text, voiceover, transitions, and audio guidance.
- Do not add lyrics, noisy voices, or music that overpowers the voiceover.

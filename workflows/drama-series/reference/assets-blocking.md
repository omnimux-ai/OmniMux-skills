# 短剧资产与站位参考

> 当 `drama-series.md` 创建角色锚点、场景锚点或生命周期道具主卡时读取；在 storyboard 阶段编写「站位记忆」文档，或为镜头行和视频 work items 编写站位事实时再次读取。
- Asset Anchors Stage 的 `execution_locks.aspect_ratio` 固定为 `16:9`，角色、场景与道具 work items 均使用这个工作画幅；Production Plan 确认的 `9:16` / `16:9` / `1:1` 是最终成片画幅，不覆盖资产工作画幅。

## 角色锚点

- 持续出现、有台词或需要特写的角色，需要**一张严格双区布局的 16:9 横版角色设定图**（短剧默认）：画布**左侧 50%** 是一个大幅正脸近景肖像（锁定五官、骨相、发型、妆造、皮肤质感；漫画/动画用已锁定漫画质感替代写实皮肤）；**右侧 50%** 是三列等宽全身视图：正面 / 侧面 / 背面，头到脚，脚完整可见，不裁切，除非剧本/状态明确要求动作，否则双手自然下垂。四个视图，一张图。
- 左右分区必须清晰：左侧正脸特写填满半幅并保持足够大；右侧三列是同一个人、同一套服装、同一发型、同一协调比例，默认中性站立。
- 背景为干净中灰 `#7c7c7c`，柔和棚拍光，完全均匀；无场景、无地面阴影、无文字/标签/水印。关键道具只作为右侧至少一个全身视图中的手持/穿戴/携带物出现，绝不单独摆在背景里。
- 用物理锚点说明**头身比**，并让它适用于每个全身列（只写一次，让三列一致），匹配已锁定风格：
  - 写实 / 电影感 / 少女漫：7.5-8 头身，头部约为总高度 1/8，腿明显长于躯干，肚脐约在离地 60% 高处。
  - 韩漫：8.5-9 头身，头相对身体很小，腿极长且优雅。
  - Chibi / Q版：2-3 头身，头巨大（约总高 1/2 到 1/3），身体和四肢短圆。
  - 3D 手办 / 盲盒：3-4 头身，大头，紧凑的风格化玩具身体。
- **使用官方布局模板作为参考图 1**：在当前 Stage 的 `ref_capsules` 注册 `id: ref_character_sheet_layout`、`name: 短剧角色设定图双区三视图布局模板` 和模板 CDN URL；将该 id 作为每个角色设定图 work item 的 `refs` 第一项（`图1` 槽位）。模板 URL：国内 `https://cdn.hailuoai.com/public_assets/opencode/character-sheet-layouts/drama-character-sheet-three-view-20260701.png`，海外 `https://cdn.hailuoai.video/public_assets/opencode/character-sheet-layouts/drama-character-sheet-three-view-20260701.png`。用户/选角参考图放在它之后（从 image 2 开始）。
- **`Image 1 is ONLY a positioning/layout guide` 这句话和布局模板图是一组，只在模板图确实是 image_paths[0] 时写这句话。** 如果模板没有传入（CDN 不可用），不要写 "Image 1 is a layout guide"；否则它会指向不存在的图片，并让后续每个 `图N` 错位。此时重新编号，让 `图1` 成为实际传入的第一张参考图，并用文字承载布局（"严格 16:9 双区版式：左 50% 大正脸，右 50% 正/侧/背全身三列"）。CDN 失败时，跳过模板图，只用 prompt 文本生成。
- 布局模板**只适用于角色设定图**。场景锚点（四宫格）和道具卡（单视图单角度）没有模板图，它们的布局由本文件的「场景锚点」和「生命周期道具主卡」规则用 prompt 文本承载；不要为场景或道具卡寻找或传入 layout-guide 图片。
- **Mode B（漫剧）的每个图片 item 都必须继承制作计划的 Medium lock。** Medium lock 为“按参考图/用户描述统一画风”时，每张生成卡和宫格都要传入风格参考图：角色设定图保持布局模板第一、风格图第二（用户/选角/道具 refs 在后）；场景卡、道具卡和 keyframe grids 把风格图放第一。Prompt 开头写 `Style reference = 图N。参考图只用于画风、线条、明暗、材质和构图节奏,不要复制参考图主体。`，不要让内容 refs 挤掉风格图。
- 每个角色都需要 `assets.md` 中的角色字段：世界观、基础设定、姿态状态、面容妆造、专属记忆锚点、发型头饰、上身或连衣服饰、下身服饰、足部鞋履、穿戴配饰，以及本集专属状态变体。
- 当剧本改变角色的服装、伤势、湿/脏状态、伪装/制服、超自然/系统印记，或携带的标志性道具（新增、改变，**或移除**，例如头饰被扔掉、外套脱下）时，为每个状态编写**单独角色设定图**，不要试图用一张图承载所有状态。Clip 随后引用与当前状态匹配的设定图，模型才不会把角色渲染回基础外观。
- 身份重要时，一张群像图不能替代逐角色锚点。
- **始终按完整锚点规范组装，不要轻量派发 prompt。** 任何时候编写、后补、重生成或单独生成角色锚点（"补一个角色" / "重新生成这个角色" / "单独出一张角色图"），`prompt` 都必须使用下面的固定模板。快捷 prompt（例如只写“生成 XX 的角色卡”）会让图像模型输出单个近景、三张松散拼贴图或错误布局。每个角色都用完整模板，不要只给第一个角色写全，后面靠记忆删减。

## 角色设定图 Prompt 模板

当布局 guide 作为 `图1` 传入时，先加上本节模板图规则要求的 layout-guide 句，再按以下精确顺序编写角色 prompt。写文本块前在 prompt 外部先解析视觉质感和人种/族裔；把视觉质感结果写到模板第二行，把具体人种/族裔值写进 `【基础设定】`。剧本明确写了人种/族裔时使用剧本值；否则从用户输入文本、故事设定、姓名、时代和地域推断。最终 prompt 只写解析后的质感句和具体人种/族裔值，不写分析规则或生产模式标签。

```text
角色设定图，左 50% 是正脸特写，右 50% 是三视图。背景统一纯中灰 #7c7c7c，无文字、无标签、无水印、无场景元素。
【视觉质感】：<分析后的结果>

【世界观】：<世界设定、时代/年代、地域、题材和故事背景>
【基础设定】：<年龄/年龄段、人种/族裔、性别、身份/职业/社会角色>
【姿态状态】：<站立/坐下/动作状态；除非剧本/状态要求动作，否则默认站立、双手自然下垂>
【面容妆造】：<气质、脸型、眉毛走势、眼型、鼻型、唇形、皮肤状态、妆造>
【专属记忆锚点】：<脸、发型、体态、服装、配饰或道具中最强的跨镜头识别锚点>
【发型头饰】：<发长/发色/发质/发型和头饰，匹配时代与阶层>
【上身/连衣服饰】：<上装或连体服饰：轮廓、面料、颜色、合身度、穿着习惯>
【下身服饰】：<分体下装：轮廓、面料、颜色、状态>
【足部鞋履】：<鞋履类型、材质、颜色、状态>
【穿戴配饰】：<穿戴/携带配饰及其叙事功能；没有则写无>
```

## 场景锚点

- 可复用地点的锚点是一张 16:9 图片，包含**同一空间的 2×2 四视图网格**：左上为正面视图（主摄像机面对主要纵深），右上为背面图（正面视图的另一面，沿同一空间纵深轴反向拍摄），左下为从左侧拍摄，右下为从右侧拍摄。它是一张图、一次图片调用，不是四张图或四次调用；可以有细分割线，但不能有文字、标签、方向标记或水印。
- 四个视图必须读起来是同一间房：布局、家具/道具、建筑材质、照明器具、文字标识、光线方向/时段、尺度和时代/地域设计在四格中一致；prompt 尾部写该场景专属穿帮禁用元素，不要只写“符合古代/现代”。锚点记录物理布局、入口/出口、主要家具/道具、光线方向/时段和可安全调度动作的区域，让下游 clips 在角度之间切换时背景不漂。
- 只有会从多个角度切镜或跨多个镜头出现的地点才生成四视图锚点。只在一个短镜头出现一次的地点保留为 clip prompt 文本；不必要的锚点会浪费生成成本和参考槽位。
- 当地点发生不可逆变化（完整 → 破坏、整洁 → 被翻乱）时，每个状态输出一张四视图锚点。

## Blocking Sheet

每个有两个或以上重要可见角色的场景，分镜列表必须携带紧凑站位信息（写在场景 header 行或空间列中，见 `storyboard.md`）：

- **primary anchor（主锚）**：每场选一个，是跨镜头保持固定且有戏剧重量的最显眼物件（灵堂→灵位，病房→病床，法庭→法官席）；当场景没有固定显眼物件时（追逐、抽象空间），退化为主角位置作为锚点。下面所有位置、面向和移动都**相对这个主锚**描述（面对它 / 背对它 / 在它左/右/前/后）。不要使用现实指南针词（南北东西）或数字坐标，模型读不懂。
- 角色位置：每个角色相对主锚的位置、距离、面向、姿态和视线。
- **role type**：标记每个角色为 `dialogue actor`（本场说话/行动）或 `on-scene witness`（在场但沉默）。`on-scene witness` 必须一直出现在所述位置（画面深处 / 边缘 / 虚焦处），直到离开，避免旁观者忽隐忽现。
- 移动原因：进入、后退、攻击、回避、揭示、交接或无变化；并写明每个角色离场时机。

编写下游 clip prompt 时，把抽象词“主锚”替换为具体物件名（写灵位 / 病床，不写主锚），模型需要真实物件才能拍出来。

```markdown
## Blocking Sheet — <scene_id>
Primary anchor (主锚): <concrete object, or protagonist position>; its screen location: <画面深处中央 / 前景 / ...>
| role | role type | position vs anchor | distance/facing | posture/eyeline | exit timing | movement/change reason |
|---|---|---|---|---|---|---|
```

## 站位记忆 Document（Blocking Memory）

上面的紧凑 Blocking Sheet 足够处理简单场景。若一个场景命中**任一**条件，就需要一份下游可反复读取的持久站位记录：**3 个或以上可见角色**、**一个场景跨多个 clips**、**剧本写了走位**、**跨场景返回（A→B→A）**，或**闪回后返回现在**。只要本集存在这样的场景，planner 就在 storyboard 阶段的**第一个文档**中编写一份 markdown canvas 文档「站位记忆 — <episode/scope>」，先于分镜列表；它是 planner-owned 连续性源，不是 executor `work_item`。内容来自剧本；分镜列表、宫格和视频 prompt 从它读取。`storyboard-confirm` 不为站位另开独立 Gate，而是在同一张联合确认卡中先展示站位记忆，再展示分镜列表；用户确认人物位置、面向、视线、进退场、走位变化和道具交接。用户提出站位修改时，在同一个 planner patch 中先更新站位记忆，再重新推导受影响的空间列。简单双人静态场景只在分镜列表保留一行紧凑 Blocking Sheet，并随分镜一起确认，不另建站位文档。

每个覆盖场景包含以下块（每个场景一个 `## 场景` 小节，并注明跨哪些 clips）：

```markdown
# 站位记忆 — <episode/scope>

## 场景：<scene_id / 场景名>（跨 <clip_a>..<clip_b>）

主锚：<concrete object；无固定显眼物时退化为主角自身位置>；场景内位置：<空间深处 / 前部 / 某固定结构旁>；光源：<方向 + 色温倾向>

### 角色站位（相对主锚，禁现实方位词 / 量化坐标）
| 角色 | 角色类型 (dialogue actor / on-scene witness) | 相对主锚位置 | 朝向（面对/背对/侧对 主锚或某角色） | 离场时机 | 走位变化（若有） |
|---|---|---|---|---|---|

### 空间与轴线（世界位置不随机位改变）
| 对话 / 动作轴 | 轴线两端 | 默认机位侧 | 允许的机位变化 |
|---|---|---|---|

### 视线 / 面向关系（每对有视线交流的角色一行，锁死默认面向）
| 角色对 | 默认面向关系 | 谁俯视/平视/仰视谁 | 例外（仅剧本明写转身/走开时） |
|---|---|---|---|

### 跨 clip 状态承接（每个 clip 一行）
| clip | 起始快照（所有在场角色的位置 / 面向 + 道具状态） | 本组可见变化 | 末态快照（下一 clip 的起点） |
|---|---|---|---|

### 道具传递链（跨镜道具，含状态变化点）
| 道具 | clip 1 | clip 2 | ... |
|---|---|---|---|
```

每个单元格的方位都相对锚点或另一个角色表达（面对 / 背对 / 侧对、左 / 右 / 前 / 后、N 步 / 一臂之距），不用现实指南针词或数字坐标。角色站位和身体面向属于**世界状态**；角色在画面左 / 中 / 右、前景肩占比属于当前机位的**镜头投影**，由分镜按轴线推导，不写成角色永久属性。正反打可以改变画面投影，但同一对话轴默认保持机位在同一侧；越轴、绕轴或角色换位只在剧本有可见动作时记录。跨场景返回时，每个角色从该场景已记录的结束状态重新开始；跨场景道具沿传递链继续，状态变化之后不重置。

`跨 clip 状态承接` 是宫格和视频共同读取的组级状态。每行都写成可独立执行的完整快照：起始列逐一写全所有在场角色和道具相对具体锚物的位置、距离、身体面向、视线、姿态与状态；变化列写清移动者的起点、方向、距离、落点及状态变化；末态列按变化后的结果再次写全所有在场角色和道具。不能只写“某人靠近”“众人反应”等摘要，也不能省略没有移动的旁观者。下一行起始快照逐项等于上一行末态；Planner 按 `clip_group_id` 直接把这一行散文化进宫格或视频 prompt，不重新猜测缺失站位。

只在站位记忆中更新世界位置、面向、在场名单和道具状态。分镜空间列复制对应 `clip_group_id` 的起始快照、本组变化和末态；keyframe grid 与 clip prompt 从同一行编译。画面左右、前景肩和景别只写入镜头投影。修改站位时，先更新站位记忆，再重新编译受影响的 shot list、grids 和 clips。

## 站位质量

- 说话角色默认面对彼此，或保持可读的三分之四视线。
- 背对背或视线断裂必须来自来源动作，例如躲藏、回避、离开、拒绝或震惊。
- 除非剧本动作改变位置，否则延续上一段角色位置。

## 跨镜头空间连续性

每个共享场景的 clip 都从**主锚**复述角色位置、面向、在场名单和道具状态。存在站位记忆时，直接复述对应行，不重新推导。

**移动方向词（相对，不用指南针）**。所有移动都相对锚点或镜头描述；不要使用南北东西：

- 朝向锚点：「朝主锚走近 / 向主锚靠拢」，不要写「朝灵位走 / 向北」。
- 远离锚点：「朝背离主锚的方向 / 向主锚反方向 / 向镜头方向走」（当锚点位于画面纵深处时），不要写「朝南门 / 向南」。
- 横向：「从主锚正前方 → 主锚左侧」，不要写「从东侧 → 西侧」。
- 被拖 / 被动：「被朝背离主锚的方向拖走 / 被推向主锚反侧」，不要写「被往南门方向拖」。
- 常见错误防护：当一个角色跪着**面对**锚点又被拖走时，他移动的是朝背离主锚的方向（朝镜头/前景），不是“朝南门”，也不是“被推向锚点”；方向必须相对锚点写，不写现实出口。

**每条移动线写全朝向 + 距离动词 + 距离刻度。** 例如：「被朝背离灵位的方向拖走 3 步，距离从一臂之距拉大到半个场景外」。距离只用步数、一臂之距或场景占比，不用米、厘米或百分比：

| 距离档 | 描述词 |
|---|---|
| 极近 | 一臂之距 / 半步 / 贴身 |
| 近 | 1-2 步 |
| 中 | 3-5 步 / 半个场景内 |
| 远 | 半个场景外 / 6+ 步 / 画面深处 |
| 出画 | 走出画面 / 锚物从视野中消失 / 出场景 |

**世界位置与镜头投影分开。** 每个角色固定相对锚点方位和身体面向；这些事实跨 clips 延续。画面左 / 中 / 右、前景肩和目标大小由当前机位按轴线推导，正反打时可以变化，但不能反向改变角色在场景中的位置。只有剧本写出移动、转身或越轴动作时，才更新世界状态。

**面向/视线表（锁定角色对，防止面对面→背对背翻转）**。每对会交换视线的角色，都要固定默认面向以及谁俯视/平视/仰视谁：「A 正面对 B,B 正面对 A;B 俯视 A,A 仰视 B」。本场所有 clips 中，这组关系不得改变，除非剧本明确写了转身 / 背过身 / 走开。不要让 clip 随意把面对面变成背对背。

**跨 clip 状态承接。** Clip N 的末态快照逐项成为 Clip N+1 的起始快照；中间只有“本组可见变化”记录的动作能改变位置、面向、在场名单和道具状态。即使本组只聚焦两名说话者，快照仍携带所有在场角色。

**跨场景 / 闪回返回。** 场景离开又返回时（A→B→A，或闪回→现在），每个角色相对锚点的位置和面向必须匹配此前结束状态，除非剧本安排了移动。新场景重新选择自己的锚点并重新声明位置；道具跨场景时，只有显式写明交接链（谁持有、什么状态、在哪个 beat）才能携带过去。

**旁观者渲染优先级（3+ 角色）**。每个 clip 在背景中至少用一句话携带每个 `on-scene witness`，写明画面角落或深焦边缘的固定位置，并保持到角色离场。

**每个 clip 的连续性检查（写每个 clip 前执行）**。按 `clip_group_id` 读取本组起始快照，确认它与上一组末态逐项相同；本组变化都有可见动作依据；末态覆盖全部在场角色和道具；机位变化遵守轴线且没有被误写成角色换位。数字坐标即使用，也只留在私有空间自检中，不进入 clip prompt。

## 状态连续性

- 一旦角色出现物理状态（伤口、淤青、血迹、撕裂或弄脏的服装、潮湿状态、伪装、疲惫、超自然/系统印记），后续每个镜头都要携带该状态，直到剧本明确解决。上一段出现的伤口，下一段也应该可见。
- 剧本移除某物后，所有后续镜头保持该物缺失，直到剧本明确让它回来。
- 物件移除后的每个 clip 都正向写明缺失状态，例如“头顶无发饰，发髻裸露”或“外套已脱去，只余内衫”；不要只依赖不含该物的锚点图。
- 在角色锚点的状态变体里记录当前激活状态及其解决 beat（或移除物及其回归 beat），让下游 keyframe 和 video work items 继承正确条件，而不是重置到基础外观。
- 当角色有多张共享同一张脸的设定图（受虐态/接管态、基础态/受伤态，同脸，只改变状态/服装/表情），基础或首次出现的设定图就是**身份基础锚点**；每个同脸变体通过下面的 base-first dependency chain 复用它，而不是从文本重新生成脸。

## 生命周期道具主卡

道具主卡是一张白底 / 干净中性背景（`#7c7c7c`）单视图单角度参考图，用于锁定单个物件的视觉一致性。它没有 layout-guide 模板图，构图完全由 prompt 文本说明。

- 道具卡只展示物件本体：单件物件独立置于中灰背景中央，使用一次完整单视图、单角度，保持轮廓、材质和尺度清晰。道具 prompt 不写持有者、手持、穿戴或人体展示。
- 柔和棚拍光；无文字、无标签、无水印、无场景元素。
- 保留项目媒介和相关色彩/材质线索，但不复制具体地点或故事空间光照。
- 材质、工艺和磨损程度必须匹配故事时代与持有者身份。

关键道具有生命周期状态变化时，必须先生成主卡，再让每个状态和每个穿戴/持有它的角色从主卡派生。

编写顺序：

1. 生成 `<prop>·master card`。
2. 提取 Prop Lock：外轮廓、主要材质、主色、核心纹样、标志性装饰的数量和相对位置。
3. 角色设定图展示角色穿戴/持有该道具时，将主卡传入 refs，并在 prompt 中写明 `KEEP Prop Lock`。
4. detached-intact / broken / dropped 等派生状态卡也传入主卡，并写明 `KEEP Prop Lock`。

禁用形式：

- 穿戴状态、脱离状态、破损状态分别只靠文本生成，没有主卡。
- 角色设定图只写“戴着凤冠 / 拿着玉佩”，但没有传入主卡。
- 破损/派生状态改变核心 Prop Lock 锚点，导致它不再像同一个物件。

## Base-First Dependency Chain

把同脸变体和同一道具的派生产物写成同一 asset-anchors Stage 内的 base-first 子链。Base 使用普通 work item；dependent 在 `refs` 中引用 base work item `id`，并把运行时图片放在 layout template 之后。为 Stage 写入串行 `execution_policy` 和原因，禁止 base 与 dependents 同批启动：

- **同脸状态变体和 alternate personas。** 先生成基础脸图。每个同脸变体（受伤/接管/换装，同脸但状态变化）引用基础图，并正向写明 `图N 是本角色的基准脸，严格锁五官、脸型、发际，仅按本卡描述改状态/服装/表情`。角色的 alternate persona 图（意识空间现代形态、闪回过去自我、梦境/投射自我，时代/服装/发型完全不同）走**同一条链**：引用基础脸图，并写明 `图N 是本角色的基准脸，严格锁五官、脸型；换成<现代/前世/...>造型：发型、服装、气质按本卡描述`。一个演员、两个造型，让观众读成同一个人。只有当剧本明确写成“另一个人的外貌”时，才不引用基础图，重新生成新脸。
- **生命周期道具主卡。** 当关键道具跨镜头改变状态（戴在身上、脱离且完整、破损、掉落、被拿走）时，先生成它的白底单视图单角度主卡，并提取 Prop Lock。每张穿戴/持有该道具的角色设定图，以及每个派生道具状态（detached / broken / dropped），都引用主卡并写明 `KEEP Prop Lock`，让物件在整个生命周期里都被看作同一个物件。主卡形式、Prop Lock 字段和禁用形式按上方「生命周期道具主卡」执行。

# Attribute Card 模板（参考图属性表）

> **何时 read**：写 Attribute Card 时（用户上传参考图后属性分析阶段）。

## 占位符语义说明

模板内容花括号里：

- `/` 默认表示**任选其一**（如 `修身 / 标准 / 宽松` 选一个填）
- `,` 表示**列出的字段全部都要填**（如 `face, hair, body` 三项都写）

## Attribute Card 模板

按角色读取属性，每张参考图输出**一张表**给用户确认。第一行总是 "参考图角色"。

模板（按角色填，无关行删掉）：

```
| 字段 | 内容 |
|------|------|
| 参考图角色 | {产品参考图 / 模特参考图 / 场景参考图 / 完整效果参考图};**这意味着会跳过 {对应 gate 列表}** |
| 品类 | {garment / cosmetic / appliance / furniture / pet / model + product} |
| 性别 / 年龄 | {女款 / 男款 / 中性 / 童装;婴儿 / 儿童 / 青少年 / 青年 / 中年 / 老年} |
| 版型 / 廓形 | {修身 / 收腰 / 标准 / 宽松 / drop-shoulder / cropped / 长款;圆领 / V领 / Polo;短袖 / 长袖 / 五分袖} |
| 颜色 | {primary + accent,带描述词,如 "ivory cream with subtle warm undertone"} |
| 材质 / 工艺 | {按品类适用项填一个: fabric weave / metal finish / gloss-matte / texture descriptor} |
| 包装文字 / Logo | {what text is on the product — 会用参考图原图保留,不重新生成} |
| **规格 / 容量 / 型号** | {举例: 500ml / 38mm 表盘 / 2L 容量 / 1080p / Type-C — 用户没明确给就空着,**禁止**编造} |
| **认证 / 合规标识** | {举例: FDA / CE / 有机 / 婴儿安全等 — 同上,没给就空着,**禁止**编造} |
| **套装内容 / 配件** | {举例: 盒内含什么、是否带充电器、是否带耳机、是否带说明书 — 同上,**禁止**编造} |
| 标志性细节 | {embroidery, seam, hardware, color-blocking 等独特元素} |
| 模特特征 (仅当模特参考图) | {以下字段全部都要写: face, hair, body, skin tone, age band, 气质, 表情} |
| 场景特征 (仅当场景参考图) | {以下字段全部都要写: location, surface, wall, lighting feel, palette, props} |
| Styling Direction (仅当完整效果参考图) | {全部要写: 风格大类, mood, 模特气质, 场景 flavor, 配色与灯光氛围 — 锁定后**逐张 prompt 复用**,不要每张图重新猜} |
| 不确定的地方 | {anything ambiguous from the reference} |
```

多张参考图：每张一张表。

## 角色分类对应表

| 角色 | 是什么 | 对下游的影响 |
|---|---|---|
| **产品参考图** | 产品本身的照片 | 产品属性锁定；会附在所有产品 / lifestyle 派发上 |
| **模特参考图** | 模特（脸 / 体 / look）的照片 | **模特 pilot gate 会被跳过**——模特已选定，直接拿用户的模特做 canonical face/body reference |
| **场景 / 风格参考图** | 场景 / 房间 / 氛围 / lifestyle vibe 的照片 | **场景 pilot 会被跳过**——场景已选定，作为所有 lifestyle 派发的场景 mood ref |
| **完整效果参考图** | 用户想要的最终成品参考（竞品 listing / Pinterest 收藏图）| 作为视觉 flavor reference；模特 + 场景 pilot 都可能被跳过 |

> **核心收益**：用户已提供的角色就是已填入的输入。**任何下游 gate / pilot 如果是为了"创建"用户已经提供的东西，就跳过**——重新走一遍 gate 是多余的、骚扰用户的（per `iron-laws.md` Meta-2）。

## 关于"禁止编造"的字段

`规格 / 容量 / 型号` `认证 / 合规标识` `套装内容 / 配件` 三个字段标了 `禁止编造`——这些是**合规高危区**，AI 不可凭"看起来像样"填补。详见 `compliance-redlines.md`。

## 产品参考图覆盖清单

属性卡确认后做覆盖检查，缺有用角度就主动问用户补。**关键**：每个缺失角度具体说**会让模型编造什么**——让用户判断"值不值得补一张"，而不是抽象 push "请提供更多角度"。

希望覆盖到的角度（越全越忠实）：

- ✅ **完整正面图**（canonical product image）
- ✅ **多个局部细节特写**：logo / 五金（拉链 / 扣 / 闭合）/ 标志性走线 / 工艺 / 织物质感 / 包装文字（如有）/ 内部 / 背面（如对 listing 重要）

话术模板：

```
你提供的商品参考图覆盖:
- ✅ 商品完整正面
- ✅ Logo 特写
- ❌ 五金 / 闭合细节 — 缺这张, 五金特写图会编造金属质感和雕刻
- ❌ 缝线 / 工艺细节 — 缺这张, 工艺特写图会编造针脚走向
建议你再补充这些局部细节图。**有就发我,没有也可以**, 缺失部位的细节图准确度会降低。
```

### 其它任务条件触发（非产品 ref 的软问）

下表的检查只在**计划集真的需要那个角度**时才触发，不无差别问。

| 触发条件 | 缺失检查 |
|---|---|
| 计划集**有模特全身**图，但用户只给了脸特写 | "需要全身参考吗？身材比例可能会偏" |
| 计划集**有包装文字**图，但用户给的图清晰度低 | "需要更高清的包装文字图吗？" |
| 计划集是**色号关键品类**（美妆 / 服饰），用户给的是手机直拍色温偏 | "色号是哪个，需要色板参考吗？" |
| 计划集**多角度商品**，用户只给了正面 | "需要 X 角度的参考吗？没有的话该角度会基于正面推测" |

**不要静默猜**：缺关键信息按上表条件触发问；硬猜就是埋雷。

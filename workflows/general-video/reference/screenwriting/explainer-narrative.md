# Explainer Narrative — 讲解叙事

## Activate When

视频目标是让观众理解概念、完成操作、看懂机制或改变一个判断时读取。故事片、纯氛围片和只需原样呈现用户讲稿的任务不套用完整结构。

## Decision Test

先明确观众、已有知识、看完后的具体能力，以及内容属于哪种解释任务：

| 模式 | 适合的主线 |
|---|---|
| 概念解释 | 问题 → 直觉模型 → 关键机制 → 应用 |
| 误解纠正 | 常见判断 → 反例/证据 → 新模型 → 影响 |
| 操作教程 | 目标 → 前置条件 → 步骤与反馈 → 验证/排错 |
| 发现式推理 | 具体问题 → 尝试 → 矛盾 → 洞察 → 推广 |
| 案例拆解 | 结果/现象 → 证据 → 原因 → 可复用原则 |

可以混合，但每段只推进一个主要理解目标。用户参考的语气和结构优先于默认模板。

## Opening Promise

开场快速建立观看承诺，可用具体问题、可验证结果、反常现象、风险或正在发生的演示。承诺必须在片中兑现；不为抓眼球夸大事实。

## Build Understanding

- 从观众已知内容出发，一次只引入完成下一步所需的新概念。
- 每个抽象概念配一个可见例子、操作、图形关系或对比。
- 用因果、条件、对比和限制连接段落；不仅限于固定转折词。
- 复杂机制先给简化模型，再说明模型在哪些边界失效。
- 教程在每个关键步骤给可观察结果，让观众知道是否做对。
- 重要洞察后留出视觉或声音空间，时长随难度和整体节奏调整。

## Evidence and Accuracy

区分事实、推断、类比和创意演示。数字、历史、产品能力和因果主张需要可追溯来源；类比要说明它帮助理解什么，并避免把类比当事实。来源冲突时不要用更流畅的说法覆盖不确定性。

## Visual Synchronization

旁白提到对象或变化时，让对应视觉在同一理解窗口出现。视觉可承担：

- 指向当前讨论对象。
- 展示步骤、状态或因果变化。
- 比较前后、大小、速度或结构。
- 给出真实证据或失败反馈。
- 暂时降低信息密度，让观众消化。

屏幕文字只保留关键词、数值、步骤名或用户要求的字幕；长段文字与复杂视觉同时出现会争夺注意力。

## Pacing

节奏由概念难度、观众熟悉度、语言、画面可读性和平台决定，不锁固定 WPM、镜头频率或概念数量。先用朗读/音频时长和视觉阅读时间估算，再压缩重复内容或拆分段落。

## Script Artifact

建议记录：受众与前置知识、观看承诺、核心问题、段落目标、事实/来源、旁白、同步视觉、预计时长、理解检查和结尾应用。字段可适配项目，不要求固定八段式。

## Review

检查开场承诺是否兑现、每段是否只推进一个理解目标、证据是否可靠、旁白与视觉是否同步、教程是否有可观察反馈、结尾是否让观众知道下一步。若内容过密，优先减少概念或拆成系列，而不是加速朗读。

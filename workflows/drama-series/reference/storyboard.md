# 短剧分镜参考

> 当 `drama-series.md` 规划 `storyboard` 阶段时读取：编写「站位记忆」文档（触发时）和「分镜列表」文档，把已确认剧本转成镜头组，并规定每个镜头行要携带的镜头级 craft（机位、光影、对白镜头设计、表演）。后续 visual-gen 阶段会把这些镜头组映射为 clip work items。

## 目标

把剧本按可一次生成的有序镜头组写入一份分镜列表。分镜只改变镜头边界、景别和机位，不改变人物、动作、场景顺序或对白；每个场景、动作 beat、状态变化和每句对白都要映射到镜头组。对白逐字复制，一句跨组时只沿自然停顿连续分配；无台词写“无”。动作 beat、对白 beat 和节奏标记只保留在 planner 私有草稿中，不创建 canvas 文档。

## 唯一编译路径：剧本 → 时长账本 → 完整分镜

分镜不是从“想做多少秒”反推的写作任务，而是一次单向编译：先逐句、逐动作算出事实，再把这份账本逐项展开为用户可见的镜头表。时长账本是分镜文本、镜头组数量、每镜秒数和本集总时长的唯一来源；最终文档只承载已经在账本中落定的镜头行。

1. **建立账本。** 按剧本顺序为每句原文和每个可见 beat 建一条连续记录，写入原文/动作、字数、适用语速、说话时长、动作或反应预留、自然切点和空间状态。此时不设镜头组数、每组秒数或整集目标秒数。
2. **由账本装组。** 从第一条记录开始累加实际时长，先得到每镜秒数和不超过 15 秒的连续组，再做相邻二次重装箱。`clip_group_count`、各组时长和 `computed_episode_duration_s` 都是此步的输出，不能先指定组数后平均分配秒数。
3. **从账本完整物化。** 按已得出的 group 顺序，逐个写出组头、起始快照、目标末态和该组全部镜头行；每一条账本记录都在一个明确镜头行中落地。文档写入以这份完整编译结果为唯一输入，内容长短不改变分镜粒度；需要重写时重新执行同一编译路径并完整替换所有组。

在用户尚未选择压缩时，用户输入、剧本标题、场次标记或摘要里的目标秒数只记录为对比偏好，不能进入上述三步的任何时长、组数或镜头分配计算。用户在分镜确认卡选择压缩后，目标秒数只用于改写出对应的短版剧本；短版剧本才是重新建立账本的事实源，目标秒数本身仍不能参与镜头、组数或秒数分配。

## 阶段流程：两份文档，一个联合确认门

1. **站位记忆先写（条件触发）**。当任何场景触发 blocking-memory 文档（3+ 可见角色 / 一个场景跨多个 clips / 剧本走位 / 跨场景返回 / 闪回返回，规范见 `assets-blocking.md`）时，将「站位记忆 — <scope>」作为本阶段第一个 document work item，**先于** shot list 编写。它的行会直接喂给 shot list 的空间列，因此必须先写。没有触发场景时，直接跳到 shot list。
2. **按唯一编译路径完成默认分镜**。写待确认分镜前完成全部账本、逐镜和整组容量计算；账本实算结果就是本集默认时长，不在分镜前发起时长冲突问询。用户主动提出但尚未选择执行的目标秒数，只在最终确认时作为对比信息。
3. **物化完整分镜列表**。账本完成后一次写入完整 shot list，并在文档顶部写明本集预计时长和逐段视频片段计划；若站位记忆覆盖某场景，则逐字复制其空间列行。用户在联合确认卡选择“压缩为 <目标时长>”后，先生成短版剧本，再以短版剧本为新事实源重新执行账本和完整物化，完整替换该分镜列表；不先展示删减提案或另开压缩问询，只展示重新拆好的分镜与实算时长供用户确认。
4. **站位、分镜与时长一起确认**。`storyboard-confirm` 在同一张确认卡中依次展示系统核算结论、站位记忆和分镜列表。用户确认预计时长是否合适，以及站位、面向、视线、进退场、道具交接、人物安排、景别、镜头组、镜头表达、动作连续性和结尾钩子；系统负责保证时长可执行、台词覆盖和超载清零。

## 其他规则位置（复用，不复述）

- **基础锁项**（mode、画幅、语言、音频策略）逐字读取制作计划（`production-plan.md`）；时长默认按本阶段时长账本实算，本阶段不重新决定其他锁项。
- **站位记忆文档规范**：触发条件、表格、相对方位纪律由 `assets-blocking.md` 负责。本文只说明何时编写它，以及 shot list 如何消费它。
- **Prompt 组装**发生在后续：clip prompts 见 `video-prompt.md`，keyframe grids 见 `scene-keyframes.md`。本阶段产出它们读取的表格。

## 分镜列表文档

每个 episode/scope 一份 canvas 文档，命名为「分镜列表 — <scope>」；始终是单个节点，不按场景拆成多个文件。文档内部按账本产出的**全部镜头组逐组分块**：`clip_group_count` 个组对应 `clip_group_count` 个具体组头和具体镜头表。每个组使用稳定 `clip_group_id`，镜号沿用该组前缀（例如 `sg_001` 下是 `001-01`、`001-02`）；这个组就是后续唯一对应的一张宫格（若启用）和一个视频 clip。

文档标题下先写本集成片规划，作为用户查看分镜时第一眼可见的信息：

```markdown
## 本集预计成片：<computed_episode_duration_s> 秒

**视频片段计划：** 共 <clip_group_count> 个，按顺序生成并拼接：<sg_001>（<时长> 秒）、<sg_002>（<时长> 秒）……
```

这里的总时长和每个片段时长必须从最终镜头组表回算；不得使用剧本标题、场次标签或摘要中写的秒数代填。

每个镜头组先写组头，再写本组镜头表：

```markdown
## 镜头组 <clip_group_id> — <本组戏剧 beat 名称>

- 剧情范围：<来源场次/对白/动作起止>
- 总时长：<秒数>
- 起始快照：<从站位记忆复制本组起点>
- 目标末态：<本组结束后下一组继承的状态>

| 镜号 | 时长 | 景别/角度 | 场景 | 画面内容与逐字台词 | 光影时辰 | 音效 | 空间（条件列） |
|---|---:|---|---|---|---|---|---|
```

逐句计数和容量计算在私有账本中完成，总字数必须等于各镜逐字台词字数之和。待确认版本逐组展开账本中全部已经通过的镜头组；超载时先把后半台词或动作移入新相邻组并重算，再从账本完整编译文档。用户看到的是完整分组和逐组最终秒数。

每个镜头行包含：

| 列 | 内容 | 纪律 |
|---|---|---|
| 镜号 | 带 group 前缀的镜号 | 跨整集连续 |
| 时长 | 例如 `9秒`；无台词写 `5秒；无台词` | 只写最终秒数；字数、语速和计算过程留在私有草稿 |
| 景别 | 全景/中景/近景/特写/远景/OTS/POV/双人构图 | 每场至少变化 3-4 种景别；全景每场最多一次 |
| 场景 | 场景名，引用场景锚点 | 地点变化开启新镜头（和新组） |
| 画面内容 | 画面 + 表演 + 该镜头逐字对白 | 表演写到微表情粒度（见 Performance design）；绝不改写台词 |
| 光影时辰 | 光线方向 + 色温 + 时段 + **叙事功能** | 叙事功能必写（见 Lighting） |
| 音效 | 环境 / 动作 / 空间声音 | 生成片段无 BGM；Post 按制作计划的 `bgm_policy` 执行 |
| 空间（条件列） | 角色位置 / 面向 / 距离 | 只用于站位记忆覆盖的场景，见下文 |

## 空间列与站位记忆：同源链路

对于被站位记忆覆盖的场景，空间列按 `clip_group_id` 复制该组的**起始快照 / 本组可见变化 / 目标末态**，使用相同的相对方位词，不重写成摘要。世界位置和身体面向来自站位记忆；画面左 / 右、前景肩和景别是当前机位的投影，只在镜头描述中表达。下游 keyframe grid 与 clip prompt 从这同一组状态编译；拆镜时发现站位要改，先回写站位记忆并重新编译，再更新受影响的分镜、宫格和视频 prompt。站位记忆不另开独立确认门，但必须作为 `storyboard-confirm` 的站位部分与分镜一起确认。

对于站位记忆未覆盖的简单场景（双人、静态、无跨 clip 连续性），在场景第一行或场景 header 行写一句紧凑 blocking：角色、画面侧位、面向/视线；其他行跳过空间列。

## 分镜列表前的私有拆分草稿

编写用户可见的分镜列表前，从已批准剧本执行下面的 scratch pass。私有时长账本是镜头、镜头组和整集全部秒数的唯一来源，也是完整分镜文档的编译输入；逐句明细只保留在私有草稿中，不创建 canvas 节点或聊天产物；Stage 只记录下文规定的汇总审计字段。

**时长隔离与重算。** 剧本中任意“时长”“约 N 秒”“90s”、场次标记、标题、括号或摘要里的数字，只能作为 `source_declared_duration_s` 的旁路记录，不能作为镜头秒数、镜头组秒数或整集实算时长。开始 scratch pass 时，所有镜头与镜头组的时长均为未计算状态；必须先从逐字台词和可见 beat 建立时长账本，再由账本依次推导镜头、镜头组和整集。即使来源数字恰好等于实算结果，也只能在全部逐条计算完成后视为巧合，不能预先采用。用户在对话中直接提出的目标时长，在未选择压缩前只作分镜确认时的偏好对比；选择压缩后，只能用于改写短版剧本，随后按短版剧本重开本 scratch pass。它不得与剧本标注的数字混用，更不能先设 `clip_group_count` 后以目标秒数平均分配每组时长。

1. **逐句对白计时**。先去除说话人标签、引号和标点，保留每个实际发音的汉字、数字和英文词；把发音串按每 10 个单位分段后再统计，不凭视觉估数。按剧本顺序为每句建立一行时长账本：原句、字数、语速档、`spoken_seconds = 字数 ÷ 该句语速`、所属动作/反应及最终承载镜头；多人对话分别计算后求和。账本中的逐句结果是后续唯一允许复制到镜头行的台词时长，不能先写 4 秒、5 秒等镜头时长再反向塞台词。
2. **可见 Beat 抽取**。逐条列出入场/离场、反应、物理动作、道具/状态变化、停顿和时间/空间转场；每个非说话 beat 预留约 1 秒，明显动作或顶点反应按来源需要增加。抽象情绪先翻译成可见动作或微表情。
3. **连续性边界标记**。标记 `[T]` 时间跳跃/闪回、`[S]` 空间跳跃、`[D]` 戏剧峰值、`[C]` roster 变化、`[L]` 对白容量边界。它们是合并时要优先保护的连续性事实，不是自动拆组命令：先判断完整转场、闪回入口/出口或反转铺垫是否能在同一 clip 内完成，只有容量或安全切点不足时才拆开。
4. **按时间顺序初装组**。从第一个 beat 开始累加 `required_group_seconds = Σ spoken_seconds + 动作/反应/换镜预留`，不以场景或来源的标注秒数预分配组容量。加入下一个完整 beat 后，若组总时长仍 ≤15 秒、有效说话时长和逐镜容量都通过，就留在当前组；若完整 beat 放不下，再检查它的非对白前置动作、视线变化或转场前半段是否能在剩余时间内自然完成。每个最终镜头的秒数必须从它承载的账本条目推导，再汇总为镜头组秒数；任何拆分都必须停在自然停顿、视觉稳定点或动作交接点，不能在句中、转场中间或冲击动作中硬切。
5. **节奏与镜头设计**。组边界确定后再标 `[钩] [缓] [爽] [顶] [尾]`，为每组选择景别、角度、运镜、反打和反应镜。快节奏通过组内短镜头和焦点变化实现，不回头压缩台词时长。
6. **相邻镜头二次重装箱**。初装组完成后，按剧情顺序扫描相邻组，目标是在不超过 15 秒且不改变对白语速的前提下尽量落在 12～15 秒。优先合并同一连续动作链、完整的闪回/转场链和反转铺垫；若下一个完整镜头放不下，但其前置非对白动作正好能填入剩余容量，则允许把这段动作并入当前组，并把对白或后续动作从自然切点交给下一组。不能为了填满而新增无关动作、重复台词或截断不可分割的表演。
7. **最后统计组数**。`clip_group_count` 是初装与二次重装箱通过检查后的结果，不是提前给定的目标。预算区间只用于发现漏戏或异常碎片化；不能为了减少组数合并超载内容，也不能因为闪回、换场或反转标签存在就放弃一次安全合并检查。

scratch pass 完成后，Storyboard Stage 的 `stage_fields` 必须写入这些可回查标量：`source_declared_duration_s`（来源有时长标记时填写，仅作旁路记录）、`dialogue_units_total`、`minimum_spoken_duration_s`、`non_speech_reserve_s`、`computed_episode_duration_s`、`clip_group_count`、`overloaded_shot_ids`、`overloaded_group_ids`、`timing_audit_passed`。`computed_episode_duration_s` 只能是时长账本推导出的全部最终镜头时长之和，不能小于最低说话时长与非说话预留的合计，也不能直接复制来源或旧目标时长；无超载时两个 id 字段写 `none`。任何超载 id 尚未清零或 `timing_audit_passed` 不是 `true` 时，继续拆分并重算，不得物化待确认分镜、不得进入 `waiting_user` 或生成确认文案。

## 镜头组：拆分整集

**先守本地容量，再尽量装满。** 一个镜头组就是未来一次视频生成，因此组总时长 **≤15 秒**；在台词语速正常、镜头容量通过的前提下，推荐尽量落在 12～15 秒。镜头数量不是组的目标：只要容量通过，组内可以用反打、反应特写、眼神跟随、道具插入或连续转场形成多个短 beat；容量不通过或没有安全切点时才拆成相邻组，不用人为动作填充空白。

**快节奏不等于快语速。** 台词按已确认文字和本组正常语速连续承载，镜头可在说话过程中紧接着切到听者反应、眼神方向、手部或道具，再回到说话者；切镜不能删字、改词、抢句尾或把台词压成高速念白。每个 beat 只承担一个清楚的视觉焦点，按剧情密度使用短促连接词和连续动作串联；当容量确实放不下、动作没有安全切点或台词无法在自然停顿处交接时，才拆成下一组。角色/场景 refs 变化本身不构成绝对拆分理由。

**一组一个 clip。** 默认一组正好变成一个 clip work item；在组内规划镜头运动，不要把它碎片化。只有容量、不可安全切分或需要明确的视觉落点时才开新组；闪回、换场和反转优先在同一组内完成，不是自动拆组信号：

| 拆分信号 | 为什么需要独立成组 |
|---|---|
| 时长溢出 | 估算动作 + 对白超过 15 秒上限；剩余内容放入相邻下一组。 |
| 对白溢出 | 某句太长，无法放进一个组，就延续到**相邻**组（见 Dialogue）。 |
| 空间跳跃 | 若完整变焦、变白、声音先行或淡入淡出能在 15 秒内完成，优先保留在同一组；放不下时在新空间已经稳定可辨处切。 |
| 时间跳跃 / 闪回 | 现在 → 闪回 → 现在优先作为完整连续转场装入同一组；容量不足时不得截断转场中段，应在闪回已稳定进入或回到现实后切。 |
| 反转 / 峰值定格 | 转折、揭示和峰值的铺垫/兑现能同组就同组；只有超载或需要明确 held 落点时才独立成组。 |
| 前置动作可填余量 | 下一镜的非对白动作、视线或道具变化能完整落在当前剩余容量内时，先并入当前组，再把后续台词从自然切点交给下一组。 |

**对白交换保持连续，不等于强塞一组。** A/B 多轮交流只有在整组容量和每条镜头容量都通过时才留在同一组；放不下时，沿说话人变化、句末或从句停顿拆到紧邻下一组。相邻组连续承载同一段对话，不在中间插入无关内容。

**单镜时长规范**：反应镜头 2-3 秒；动作镜头 3-5 秒；建立/定调镜头 4-6 秒；承载长台词的镜头拉长到 字数÷3.5（上限：mode A ≤8 秒，mode B ≤15 秒）。时长按目的变化，完全均匀会让节奏变平。

**反应优先随台词，但服从容量。** 能放下时，把听者反应、微表情和说话人的画外延续留在同组；放不下时，让反应与下一句对白或下一动作组成紧邻组。剧本明确的沉默、动作、空间建立、反转峰值或最终 cliffhanger 可以形成无台词组，不为满足“每组有台词”而挤压前后对白。

**组数只做回查，不做配额。** 组数明显过多时必须先做相邻镜头二次重装箱，检查同一动作链、转场链、闪回链和可填入的前置动作；明显过少时检查是否漏了对白、动作或连续性交接。只有重新核算后仍满足逐句、逐镜和整组容量，才允许合并；不能为了靠近目标时长而合并超载内容，也不能把可以安全连续呈现的内容过早拆开。

**本集时长核算。** 不论剧本是否标注过秒数，也不论用户是否主动说过目标时长，都必须先在没有任何来源秒数或目标秒数参与分配的前提下，完成逐句、逐镜和整组容量核算，并先尝试按自然停顿拆成不超过 15 秒的连续镜头组。`computed_episode_duration_s` 来自时长账本和最终镜头表，是本集默认采用的成片时长；即使剧本完全没有时间描述，也走同一套计算。用户主动提出但尚未选择执行的目标秒数，仅在分镜确认中与实算值并列展示；用户选择压缩后，目标秒数只能指导短版剧本的删改范围，不能直接驱动镜头、镜头组或秒数分配。绝不要为了卡数字静默压缩对白或删除 beats。

本集最终组要落在 cliffhanger：以 hook 结尾，即未回答的问题、危险或反转；最后一个 beat 在切断前短暂 freeze。

## 节奏标记（planner 内部，分组时应用）

拆解 beats 时（私有草稿，绝不成文档），标记整集五个节奏段，并让它们驱动每段镜头密度和时长。首次编写版本就应带这个形状，不要等用户抱怨“反杀段不够炸”再补；在**预算时长内部**重新分配密度，不要膨胀总时长。

| 段 | 位置 | 镜头密度要求 |
|---|---|---|
| [钩] 开场钩子 | 前 8-15 秒 | 比全集平均 +30%：短镜头 + 快切 |
| [缓] 中段铺垫/缓冲 | 钩子后 → 反转前 | 比平均 -20%：中长镜头 + 慢推/静态，蓄势 |
| [爽] 反杀/反转/撕逼 | 集中后段 | **比平均 +50%**：极短镜头 + 快切 + 反应镜头 |
| [顶] 顶点定格 | 反杀最高点 | 单镜延长 **1.5-2×** + 环境音收紧，给爆点留白 |
| [尾] 集尾钩子 | 末 5-10 秒 | 比平均 +20%：短镜头，切在悬念上 |

[爽] 的密度跳跃和 [顶] 的 held shot 是强制要求；密度平直的集数会显得合格但没有生命力。[缓] 与 [爽] 的对比让爽感落地，要保护慢段，而不是把所有段抹平。

## 对白：语速、负载和拆分

**语速档（SSOT，台词速度和字数上限的单一事实源）**。确定组时长前先估算 spoken time；按戏剧强度选择档位：

| 戏剧强度 | 语速 | 容量计算 |
|---|---|---|
| 深情 / 缓慢陈述 / 心理独白 / 顶点戏 | 3.0 字/秒 | 本句字数 ÷ 3.0 = 本句最低说话时长 |
| 常态（日常对白 / 平静交流 / 独白）默认软顶 | 3.5 字/秒 | 本句字数 ÷ 3.5 = 本句最低说话时长 |
| 撕逼 / 怒吼 / 互怼 / 高对抗，硬顶 | 4.0 字/秒 | 本句字数 ÷ 4.0 = 本句最低说话时长 |
| 极端撕逼（仅持续怒吼、抢话或高速爆发；需 warn「语速偏快，注意留白」） | 4.5 字/秒 | 本句字数 ÷ 4.5 = 本句最低说话时长；冷声、压低、平静、停顿按 3.0-3.5 |
| 禁区 | > 4.5 字/秒 | 禁止：拉长本组或拆到相邻组 |

台词字数只统计逐字台词中实际发音的汉字、数字和英文词，不含标点、引号或说话人标签；同一句跨镜时按各镜实际承载内容分别计数，组总字数只能由逐镜字数相加。整组最低需要时长按逐句求和：`required_group_seconds = Σ(每句字数 ÷ 该句语速) + non_speech_reserve`；同组各句按各自表演选择语速，不因“高对抗”统一套 4.0 或 4.5。`non_speech_reserve` 至少 2 秒，本组每个独立动作、反应、停顿或换镜 beat 约预留 1 秒，取两者较大值；结果超过 15 秒时直接拆组。

分配到单条镜头行的台词按 `spoken_seconds = dialogue_chars ÷ speed`、`duration_s = ceil(spoken_seconds + shot_reserve)` 计算；该 `duration_s` 就是镜头行唯一的最终时长，禁止另行分配更短时长或同时填写不同的“逐镜容量”值。`shot_reserve` 至少 1 秒并覆盖该镜动作、表情和换气，不能向下取整。当前组仍不超过 15 秒时直接使用该时长；否则沿句号 / 问号 / 破折号 / 省略号 / 逗号等自然停顿，把原文实际分配到本组后续镜头或紧邻下一组。每个承载镜头只写自己实际说出的台词段和对应时长，不能把完整台词留在超载镜头里再标注“画外延续”。

**过载处理顺序：反碎片化，绝不靠删字解决**

1. **先核算真实需要时长**：逐句说话时长求和，再加入本组实际动作、反应、停顿和换镜预留；不用固定“只留 2 秒”覆盖所有场景。
2. **未到 15 秒时先做容量填充**：优先加入下一个完整 beat；完整 beat 放不下时，再加入能在剩余容量内自然结束的非对白前置动作、视线、道具或转场段。目标是 12～15 秒，不提高语速、不新增无关动作。
3. **仍超过 15 秒或没有安全切点才拆相邻组**：按说话人变化、句末、破折号/省略号、视觉稳定点或动作交接切分；前后组保持对白、动作、空间和声音连续。
4. **二次重装箱后再统计**：逐组回算 `Σ spoken_seconds + non_speech_reserve`，确认合并没有截断转场、闪回入口/出口、反转铺垫或不可分割动作，并把最终组数和最终总时长写入 Stage。
5. 无论实算总时长是多少，都采用实算结果完成当前分镜。对白完整性优先于模型自行猜测；不要静默改写或删减。

**长台词从哪里拆。** 按自然停顿优先级：

1. 说话人变化（一人说完，另一人接话或反应），最干净。
2. 同一说话人句末停顿（句号、问号、破折号、省略号）。
3. 逗号处从句停顿。
4. 绝不在没有停顿的词组中间切断，那会读成截断。

**非说话人画面拍什么。** 声音作为画外音继续时，画面切到与故事相关的内容，并尽量用更紧景别让切换可读：

- 听者反应：瞳孔、眉毛、下颌、喉结。
- 说话人自己的手：攥住衣摆、指节发白。
- 回应台词含义的道具或环境 beat（不要无关插入）。
- 明确标记这段音频是该句台词的画外延续，让下游生成知道画面不是说话嘴型。
- 三次以上这种切换中至少混合两种类型，避免全是反应脸或全是手。

**长台词可以跨镜头，但不能超出组容量。** 说话过程中可切听者反应、手部、道具或环境，并将同一句标为画外延续；这些切换分别成为本组镜头行。若逐句说话时长加动作/反应预留超过 15 秒，就在自然停顿处拆成相邻组，不把所有反应继续塞进同一 clip。

**当长台词确实跨两个组时**，两个承载镜头必须有清晰景别或角度变化，否则切口会像没拆开。

## 分镜确认中的时长调整

分镜联合确认前，先完成完整剧本的时长账本和自然停顿拆分，直接进入同一张 `storyboard-confirm` 卡片；不得为时长单独弹出冲突问询或要求用户在资产前决定时长。确认卡除站位和分镜设计外，同时展示本集实算时长、片段数和时长选择。

确认卡只提供“按实算时长与当前分镜继续”。当前完整剧本、时长账本和分镜直接作为后续唯一来源。

**多音同字重复。** 当一句台词包含相邻重复字但读音不同，TTS 可能压成一种读法；调用一次 `question`，提供“自然改写（推荐）/ 保留原文”，自然改写只处理发音歧义并展示具体改写文本。

## storyboard-confirm 前分组检查清单

确认门前执行本检查。任何失败都先修表，再让用户 review：

1. 文档按 `## 镜头组 <clip_group_id>` 明确分块；每条镜头行只属于一个组，组 id 唯一且按剧情顺序连续。
2. 私有草稿中每句台词都完成每 10 个发音单位分段计数，`dialogue_units_total` 必须是从完整剧本逐句统计出的正整数，不能写 `false`、估算值或剧本标注时长；每组总字数等于各镜实际台词字数之和，各句语速、最低说话时长和动作/反应预留都能从逐字台词回算。待确认文档只展示修正后的分组和最终秒数。
3. 每组总时长不超过 15 秒，通常不少于 6 秒，并在正常语速与容量通过时尽量落在 12～15 秒；对每一条含对白的镜头逐一确认 `台词字数 ÷ 语速 + 动作/换气/反应预留 ≤ 本镜时长`。任意一条镜头失败都属于硬失败，不论该镜是 4 秒、8 秒还是 15 秒；必须沿自然停顿、视觉稳定点或动作交接处继续拆分，不能为凑时长合并回超载镜头。
4. 将剧本逐字对白与最终分镜逐条对账：每句必须完整出现一次并落到明确镜头，禁止漏句、改词、重复台词、把台词藏进摘要或突然提高语速。超载台词只能沿自然停顿连续分配到后续镜头或紧邻下一组；对账未通过时不得进入确认。
5. 空间跳跃、时间跳跃、闪回和反转先检查是否能以完整转场链在同一组内呈现；只有真实容量溢出、没有安全切点或需要明确视觉落点时才形成组边界。纯动作/反应组有明确剧本功能；可安全填入当前余量的前置动作不得被过早拆开。
6. 起始快照和目标末态与站位记忆同源；下一组起始快照逐项继承上一组末态。
7. `clip_group_count` 等于文档中的镜头组块数量；后续每个组只对应一个宫格 work item（若启用）和一个 visual-gen work item。
8. 剧本每个场景、动作 beat 和每句逐字台词均被覆盖；组数是通过上述检查后的结果，不再拿经验区间反向压缩。
9. Stage 的 `dialogue_units_total`、`minimum_spoken_duration_s`、`non_speech_reserve_s`、`computed_episode_duration_s` 必须与当前事实源剧本和最终分镜表回算一致；`computed_episode_duration_s` 必须同时等于全部最终镜头行时长和全部最终镜头组时长，不能只等于对白时长加一个未落到镜头的预留值。只要有任何漏对白、单镜容量失败或镜头/镜头组/整集三方总时长不一致，就不得写 `overloaded_shot_ids=none` 或 `timing_audit_passed=true`，也不得进入 `storyboard-confirm`。所有对白镜头逐条通过、完整对白对账通过、`overloaded_shot_ids=none`、`overloaded_group_ids=none`、`timing_audit_passed=true` 后才允许确认。

联合确认文案必须根据当前项目的核算结果、站位记忆和分镜列表动态生成，不能套用固定秒数、固定片段数或与本项目无关的角色、场景和道具描述。使用短段落或项目符号，按以下顺序表达：

1. 先写“分镜已拆分完成，系统检查通过”。来源存在时长标记时，用“原剧本标注约 <source_declared_duration_s> 秒；按完整保留台词和正常表演节奏核算，预计成片约 <computed_episode_duration_s> 秒”解释差异；来源没有时长标记时只展示预计成片时长。用户主动给过目标时长时，同时展示其目标与实算时长的差异，但不将其描述为冲突。
2. 把 `clip_group_count` 翻译成“后续将生成 <clip_group_count> 个视频片段”，并把已通过的容量检查翻译成“当前确认版本的台词和场景均可完整呈现，无需删减”。不要向用户展示“对白发音单位”“超载镜头 0 个”、字段名、id 列表或 `timing_audit_passed` 等内部审计信息。
3. 用“请确认以下内容是否符合预期”进入两部分创作检查。人物站位部分从本项目站位记忆中选出最需要用户关注的 2-4 项，直接写角色名、场景锚点、面向/视线、进退场或关键道具交接；没有站位记忆时省略该部分。分镜设计部分从本项目分镜列表中选出最需要关注的 2-4 项，直接写关键人物安排、重要景别或镜头切换、动作承接、反转/高潮和结尾钩子。不要用一套通用名词清单替代本项目的具体内容。
4. 在创作检查后补一句本项目的时长确认：“请同时确认预计成片时长是否符合预期。” 不得另开时长冲突卡或提供填写目标时长、指定删减内容的入口。

将上述核算结论、创作检查和时长确认提示写入 Storyboard Stage 的 `review.after_execution`，不得省略或写 `[]`。`review_text` 只呈现这些用户可核对的结果，不定义确认按钮或重复展开修改流程；Stage review 统一提供确认选项和自定义修改入口。只让用户审核创作安排与预计时长是否符合预期；提交审阅前必须完成台词容量校验，用户不负责判断台词是否放得下。

**多音同字重复。** 当一句台词包含相邻重复字但读音不同，TTS 可能压成一种读法；提交前按上文多音同字规则处理。

**情绪标注。** 每句 spoken line 标三件事，避免只写 "(angry)" 这种扁平标签：

- 声音质感：低吼、颤抖、沙哑、带气声。
- 身体泄露：咬紧牙、喉结滚动、鼻翼张开。
- 情绪弧线：压到破裂前、哭到失控、忍住后崩开。

下游生成会把这些转成口型、表情和 delivery，让音画同步。

## 镜头语言服务故事

景别、角度和运动都是戏剧选择，不是默认值。每个选择都要承载 beat 意图，并随情绪变化。

**景别跟随焦点。**

- 拉宽用于建立空间、尺度或孤立感。
- 当 beat 落在眼神、颤抖或屏息上时，收紧到特写或 ECU。
- 同一主体上的切换至少变化一级景别（或机位约 30°），让切口读成有意 coverage，而不是 jump cut。

**整场景别纪律**（按场景应用，不只按切口）：

- 工作景别集合是 全景 / 中景 / 近景 / 特写 / 远景 / OTS（过肩反打）/ POV / relation shot（双人构图）。不要让同一场连续镜头都停在同一景别，至少跨 3-4 种不同景别变化。
- **慎用 wide（全景）**：每场或每个 clip group 最多一次，只用于建立空间。主体部分靠近景 / 特写 / relation shots（过肩、双人、medium-close 反打）。
- 多角色对白优先用 OTS reverse-angle（过肩反打），而不是平直 medium-wide（中景大全景）；反打组承载交流并保持视线可读。

**角度跟随权力和状态。**

- 平视表示人物之间平等。
- 俯拍表示支配、怜悯或崩塌。
- 低角度表示威胁、决心或压迫性存在。
- 只有当舞台中的高低关系确实变化时才改变角度。

**运动跟随感受。**

- 慢推制造压力或亲密。
- 甩镜或手持制造不稳定并提升紧张。
- 锁机让表演自行呼吸。
- 揭示运动（dolly、crane、rack）用于兑现爽点。
- 运动要匹配 beat 正在发生的事；有意识的静止也可以是选择。

整个序列要变化。如果每组都变成同一种慢推，戏会被抹平；反应 beat、动作 beat 和定调 beat 不该用同一种镜头运动。

## 镜头与光学承载情绪

除构图外，镜头观感是一组电影摄影意图（ARRI 级参考是合适基线）。每组都要写成**一个值 + 一个与该 beat 相关的理由**，让下游 clip prompt 继承意图，而不是只看到裸数字：

- **光圈 / 景深**：浅景深隔离脸，让背景成为情绪 wash；更深景深用于保留多人空间关系和压力。
- **焦距**：较广（约 35mm）用于空间语境和动作可读；自然（约 50mm）；较长（65-100mm）压缩脸部并强化情绪。
- **快门**：标准 180° 给自然运动模糊；更短快门为打击和破碎瞬间增加紧张和冲击清晰度。
- **ISO / 曝光**：烛光、火光和夜内景可提高，同时控制颗粒。
- **动态范围**：宽容度（约 15 stops）同时保护火光高光和阴影细节；火、烛、夜景要点名。
- **色彩科学 / gamma**：电影色彩响应保持肤色自然，火光和阴影层次分明；log 曲线保留调色余地。

场景类型起点：

| 场景类型 | 光学倾向 |
|---|---|
| 濒死 / 崩溃特写 | 更浅 DoF、长焦、柔和运动模糊；保护眼神、唇颤和皮肤 |
| 决定性反击 / 武器动作 | 标准到短快门、中等 DoF；动作清晰且保留可信模糊 |
| 被包围 / 群体压迫 | 中到深 DoF、较广镜头；保持空间关系 |
| 火 / 烛 / 夜 | 强调动态范围，让高光保住、暗部有细节 |
| 克制戏剧 | 自然焦段、柔和 DoF、低对比但保留微表情 |

用户不决定时，仍要在组上记录数值和理由；不要让组带着没解释的 look 交付。

## 光影和时辰承载意义

每个镜头写明光线的**方向 + 色温 + 时段（晨/午/暮/夜）**，并且写上最容易漏掉的部分：**光线服务的叙事功能**，不只是物理值。

- 方向和质感：主光方向（侧、背、顶、底）、硬度、反差，按 beat 情绪选择。
- 色温和时段：冷/暖及其暗示的时间；连续场景内保持一致，除非故事推进到另一个时间。
- 叙事功能是强制项：说明光在戏剧上做什么，例如“冷主光 vs 暖实用灯暗示两个世界的对立”，“光线从暖转冷 tracks the character's hope collapsing”，“single hard top-light isolates the accused”。没有叙事功能的光影说明是不完整的。
- 火 / 烛 / 夜段落要与上面的宽动态范围光学说明配合，让高光和暗部都保留细节。

## 表演设计

表演要写到具体、可读的身体粒度，而不是抽象情绪词。

**脸部（FACS / AU）**。用动作单元命名关键表情，而不是只写“悲伤”或“崩溃”：

- Inner-brow raise（AU1）：悲伤、恳求。
- Brow-knot（AU4）：压抑痛苦、忍耐。
- Upper-lid raise（AU5）：恐惧。
- Lid-tighten（AU7）：抵抗、拒绝。
- Lip-corner depress（AU15）：垮掉。
- Chin raise（AU17）：吞下哭声。
- Lips part（AU25）：呼吸即将变成话语。
- Jaw drop（AU26）和 lid closure（AU43）：意识衰退。

**诚实地写濒死。** 焦点漂移、眼神小幅游移、上眼睑放弃、嘴唇微张、下颌失去张力、最后一次失败吞咽、胸口起伏后停止。是安静消退，不是戏剧化突然关机。

**身体链。** 高情绪或受伤时，按顺序写链条：脸绷紧 → 颈部撑住或松掉 → 肩膀下沉或抬起 → 呼吸不完整 → 腹部保护 → 脊柱弓起或塌下 → 重量经过髋和膝转移 → 手指攥紧或失去抓握。

**无意识泄露。** 抓胸前衣料、手指揉袖口、手半抬又放弃、用吞咽遮掩情绪、屏住呼吸、避开视线。

**物理真实。**

- 头发比动作慢一拍（约 0.3-0.5s）。
- 布料在转身或跌倒时有惯性。
- 珠宝和刀刃要读出重量。
- 跌倒按肩-肘-髋-膝顺序落地。
- 尘土、火星和血迹与运动互动，而不是浮在表面。

## 不通过视频串联保持连续性

Clips 之间的连续性来自共享的**角色和场景锚点图片**，以及每个 clip 上写好的 **`continuity` 字段**，不是把上一段生成视频再作为参考图喂回去。每个 clip 都重新生成；锚点保持身份和空间，continuity 文本说明要延续什么。

- 连续组使用同一个地点视觉锚点；除非剧本写了走位，否则每个角色相对锚点的位置和面向保持稳定（这些事实来自站位记忆 / shot list 空间列，规范见 `assets-blocking.md`）。
- 在 `continuity` 字段中，用普通故事语言写入 incoming visual state：当前伤势和服装状态、谁相对锚点在哪里、已建立视线关系，以及任何道具交接；这样下一段 clip 继承状态，而不是重置回基础外观。
- Incoming state 要写成上一段 clip 的**视觉结束帧**，不是剧情摘要：例如“目光从墙上血字收回，右手仍钳制不松，红嫁衣左肩滑落”（姿态、表情、位置、手里有什么、身体状态），绝不写“叮嘱完了”或“上一段结束”。模型只能继承能被文字渲染的东西；剧情复述渲染不出画面。
- 物理状态（伤口、血迹、撕裂或潮湿服装、伪装、疲惫）一旦出现，就在后续每个 clip 中保持可见，直到剧本解决它。
- 单个 clip 内部用镜头运动实现 speaker→listener→speaker 的视点切换，这比拼接独立 takes 更稳定。跨 clips 时，用锚点和 continuity 文本携带贯穿线，绝不要引用上一段渲染结果。

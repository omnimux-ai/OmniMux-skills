# 短剧制作计划参考

> 当 `drama-series.md` 创建或修订「制作计划（Production Plan）」文档时读取。制作计划是资产生成前的控制文档，用来锁定基础信息、检查用户提供物料、锚定视觉风格，并列出要生成的资产。

## 目标

创建一份名为「制作计划 — <episode/scope>」的 canvas 控制文档，写入基础锁项、物料质检、风格锚点和资产清单。不要复述角色小传、分集目录、道具故事线或付费墙；这些内容只从剧本文档读取。

## 文档结构

```markdown
# 制作计划 — <episode/scope>

## 基础信息
| 项 | 值 | 来源 |
|---|---|---|
| 类型/题材/时代地域 | <如 古装权谋·架空古代中原 / 悬疑·1990s 县城> | 用户输入 / 剧本反推 |
| 集数与目标范围 | <EP1 / EP1-3> | 用户输入（默认先做第 1 集） |
| 时长处理 | 按剧本实际体量拆分 | 系统默认；分镜阶段按完整台词、动作和正常表演节奏实算 |
| 用户目标时长（仅用户主动提出时写入） | <如 90 秒> | 用户主动说明；作为分镜确认时的对比偏好，不作为前置锁项 |
| 生产模式 | <A 真人实拍 / B 漫剧> | 用户输入 |
| 视觉子风格 | <仅 mode B，如 韩漫> | 用户输入 / 物料反推 |
| 画幅 | <9:16 默认 / 16:9 / 1:1> | 用户输入 |
| 语言 | <中文 / ...> | 用户输入 |
| 字幕策略 | <视频派单前问询锁定：不加字幕 / 烧录字幕 / 字幕文件> | Visual Gen 前问询 |
| 音频策略 | <native video> | 按 mode 推导（见下） |
| BGM 策略 | <生成（推荐） / 用户提供 / 不生成> |

## 物料质检
| 物料 | 质检结果 | 建议 |
|---|---|---|

## 视觉风格锚点
- Medium lock: <一句定稿的媒介描述>
- Style brief: <3-5 个调性关键词>
- Color palette: <2-3 个具体色 + 角色/用途>
- Lighting: <方向 / 质感 / 色温>

## 资产清单
### 角色
| id | 角色 | 功能 | 本集状态变体 |
|---|---|---|---|
### 场景
| id | 场景 | 复用情况（几场/几个机位） | 时代/地域/穿帮禁用 | 光线/时辰 |
|---|---|---|---|---|
### 道具
| id | 道具 | 生命周期（佩戴/摘下/损毁） | 归属角色 |
|---|---|---|---|
```

## Questions

编写 Production Plan 前，planner 是制作前基础锁项问询的唯一发起者，并且只调用一次合并后的 `question`：把本阶段需要但尚未确认的全部独立制作选项放进同一次调用，每项使用独立 question 对象，推荐项放第一位，不把多个锁项拼成一个组合选项。`active_project_locks` 中只有来源明确为用户本轮主动说明或已回答问询的具体值才算已确认，不再重复询问；剧本标签、来源推断、候选值和默认值都不能代替本轮确认，只能作为问询中的预填信息。所有回答写成具体锁项前不得物化 Production Plan 或 author Asset Anchors Stage。

| 问询项 | 选项 | 用户可见说明 | 结果写入 |
|---|---|---|---|
| 制作模式 | A 真人实拍 / B 漫剧 | 真人演员表演与原生对白，或统一的漫画/动画媒介。 | 基础信息.制作模式 |
| 类型/题材 | 按剧本给出互斥选项，最匹配项（推荐） | 只确认主导题材，避免后续风格和叙事方向漂移。 | 基础信息.类型/题材 |
| 时代/地域 | 按剧本给出互斥选项，最匹配项（推荐） | 决定建筑、陈设、服化道、照明、标识和禁用元素。 | 基础信息.时代/地域 |
| 画幅 | 9:16（推荐）/ 16:9 / 1:1 | 9:16：手机全屏短剧首选，常见于抖音、快手、红果、七猫、ReelShort、DramaBox、TikTok 等移动短剧平台；16:9：适合横屏剧集、电视/OTT、B站和 YouTube；1:1：适合社交 Feed、宣发切片和方形预览，不是完整短剧正片首选。 | 基础信息.画幅 |
| 集数范围 | 先做第 1 集（推荐）/ 用户指定范围 | 明确本轮只处理哪些集数，未确认的集数不提前创作或生成。 | 基础信息.集数范围 |
| BGM | 生成（推荐）/ 用户提供 / 不生成 | 生成片段不烘焙 BGM；Post 按此选择生成、使用用户音轨或保持无 BGM。 | 基础信息.BGM 策略 |

画幅是制作前必确认项；用户未指定或只由来源推断时，仍要展示问询，不能静默采用默认值。时长不在此阶段询问：默认按剧本实际体量拆分，待分镜完成后与分镜设计一起确认。用户主动提出的目标秒数才记录为时长偏好；没有主动说明时省略该行，不在资产前要求用户决定压缩、删减或延长。

二轮问询：Mode B 且视觉子风格缺失时，调用一次 `question`。

| 问询项 | 选项 | 结果写入 |
|---|---|---|
| 视觉子风格 | 2D 动漫（推荐）/ 3D 动画 | 基础信息.视觉子风格与 Medium lock |


## Visual Gen 前的视频模型与字幕问询

编写 `visual-gen` Stage 前，先调用一次 `question`，其中包含“视频模型”和“字幕策略”两个独立问题。MiniMax H3、Seedance 2.0 Fast 与 Seedance 2.0 Mini 选定后直接锁定其当前默认分辨率；只有选择 Seedance 2.0 或自定义模型时，才追加一次依赖该模型答案的分辨率问询。模型、分辨率和字幕策略构成同一段执行前决策流程，完成后不得再次确认这些锁项。Planner 按已确认分镜、站位记忆和模型骨架编译全部最终 Prompt，并在内部完成来源、结构、填空字段、镜头密度、有序 refs、声音、末态和重试保真检查；不通过时先补齐或阻塞。检查通过后，`review.before_execution` 只写“查看或修改每条最终视频提示词”和“核对每条提示词使用的有序参考素材”，让用户在可编辑执行计划中确认后再生成；不得在该确认中重复询问模型、字幕、分辨率、画幅或已确认的分镜/宫格。`visual-gen` 的阶段 `goal` 只描述编译并生成视频片段，不得写“等待用户检查/确认后生成”或同义等待语句；执行前检查只能由 `review.before_execution` 表示。用户确认可编辑执行计划后，这个检查门即视为已消费，阶段直接进入生成；恢复或重试时不得重新发起同一确认。

视频模型使用以下官方展示名和说明：

| 展示名 | 用户可见说明 |
|---|---|
| MiniMax H3 | 推荐。当前默认以 2K 生成，费用更低、清晰度更高；写实人脸、自然动作、原生对白/环境声和多模态参考稳定。 |
| Seedance 2.0 | 多镜头和全模态参考控制更强；选择后可按实时能力选择分辨率。 |
| Seedance 2.0 Fast | 默认 720P；适合快速试片和批量迭代。 |
| Seedance 2.0 Mini | 默认 720P；适合轻量草稿和简单镜头。 |
| 自定义模型 | 用户填写模型名称。 |

初始问询始终展示全部预置模型，MiniMax H3 放在推荐位置；不从此前选择的分辨率排序或推荐。模型答案返回后调用 `hub_list_capabilities`：MiniMax H3 锁定当前默认档位；Seedance 2.0 Fast 和 Seedance 2.0 Mini 锁定 720P；Seedance 2.0 只展示实时可用的 720P、1080P、4K 档位；自定义模型只展示实时能力支持的用户可见档位。不得硬编码 MiniMax H3 的未来分辨率，也不得静默将一个档位替换为另一个档位。

分辨率答案写入后必须再次用实时能力清单复核；若预置模型的默认档位不可用，或自定义模型没有可用档位，返回约束冲突，不得静默换模型或分辨率。通过前不得派单；分辨率只写入 Visual Gen 的 `execution_locks.resolution`，不回写 Production Plan。

字幕选项语义固定为“不加字幕（推荐）”“生成并烧录字幕”“只生成字幕文件”，实际 label 与简短说明必须翻译为 `working_language`。最终写入 `execution_locks.vendor_model_policy: {vendor, model_id}`、`execution_locks.resolution` 和 `execution_locks.subtitle_policy`。预置展示名只映射到实时能力中对应的官方 ID：`MiniMax H3` → `{vendor: MiniMax, model_id: MiniMax H3}`，`Seedance 2.0` → `{vendor: seedance, model_id: seedance2.0}`，`Seedance 2.0 Fast` → `{vendor: seedance, model_id: seedance2.0-fast}`，`Seedance 2.0 Mini` → `{vendor: seedance, model_id: seedance2.0-mini}`；自定义模型必须通过 `hub_list_capabilities` 校验，不得用展示别名派单或替换为其他模型。

## 基础信息（Meta Locks）

- `Questions` 的回答必须以**具体值**写在这里。画幅必须有本轮制作前问询的回答；来源剧本或默认值只能用于生成候选说明，不能替代确认。时长处理固定写为“按剧本实际体量拆分”，实际秒数由分镜核算后写入分镜列表顶部；用户主动说明的目标秒数可记录为时长偏好。字幕不在制作计划阶段最终锁定，必须在 Visual Gen 派单前单独问询。时代/年代与地域必须单独锁定，因为它会决定场景建筑制式、室内陈设、照明技术、街景交通、文字标识和禁用元素。
- 生产模式、语言、音频/BGM 策略和媒介描述驱动所有下游阶段。这里确认的画幅是最终交付锁：Visual Gen 与 Post 必须继承；Asset Anchors 使用 `assets-blocking.md` 规定的 16:9 工作画幅，Scene Keyframes 使用 `scene-keyframes.md` 规定的样式工作画幅（黑白八宫格 16:9、彩色九宫格 1:1），都不得被成片画幅覆盖。Visual Gen 追加已确认的字幕策略与视频模型锁。

## 物料质检（Supplied-Material Check）

当用户提供图片、剧本或风格参考时，每个物料写一行：它是否支撑下游连续性（角色图支撑脸/体型/服装一致；道具图支撑 Prop Lock；场景图支撑多角度空间；风格图风格可提取）。不通过的物料要给出具体建议（重生成 / 放大修复 / 用户重新上传）。全部通过时，一行“物料无问题”即可。没有用户提供物料时，省略本节。

### Questions

物料质检不通过时，调用一次 `question`；每项必须使用独立 question 对象，推荐项放第一位，不允许将多项问询混在一起。

| 问询项 | 选项 | 结果写入 |
|---|---|---|
| 不合格物料 | 根据质检结论推荐：带修复接受 / 替换 | 物料质检.处理方式 |

备注：问询中写明具体物料、不通过原因和修复建议；全部通过时不问。

## 视觉风格锚点（Visual Style Anchor）

下游 prompts 逐字保留已确认的 **Medium lock**，只继承当前产物相关的风格约束。资产卡使用中性卡片设置，并加入相关时代、材质、阶层、色彩和禁用元素；场景锚点、宫格和 clips 使用当前地点、时间和空间的光照。不要把完整 Color palette 或 Lighting 粘进无关产物。Style brief 从剧本调性提取，Color palette 从主导情绪提取，Lighting 从关键场景提取。
Mode A（真人实拍）的视觉质感拆为两层：通用环境层固定为 `写实质感`，可用于角色、场景、道具、宫格和视频；人物外观层固定为 `真实皮肤质感；自然真实的人类面部特征，带有轻微的生理不完美。`，只允许用于画面中有可见人物的产物。
通用环境层写入 `Medium lock`，用户选择真人模式后不可省略；人物外观层不写入 `Medium lock`，由下游按产物是否有可见人物条件性附加。
Mode B 的 Medium lock 必须包含视觉子风格映射：`2D动漫` -> 写“二次元2d动漫风格、干净线稿、平涂上色”；`3D动画` -> 写“高精细动漫游戏CG、3D高精建模质感”。

## 资产清单（Asset Inventory）

资产清单就是后续 Asset Anchors Stage 一次性审阅的内容。这里要按角色、道具、场景三组精确列出锚点阶段会生成什么：持续出现的角色（包含本集状态变体，如受伤、换装、伪装、摘除）、值得生成主卡的生命周期道具（按 `assets.md` 的建卡判断筛选，按 `assets-blocking.md` 的主卡规则执行），以及可复用地点（只列会从多角度切镜的地点；只出现一次的地点保留为 prompt 文本）。每个场景行都要写时代/地域/穿帮禁用：把“古代 / 现代 / 近未来”转成可见的建筑、陈设、照明、标识和交通限制，避免场景卡只剩通用房间或通用街道。逐场对白和 beat **不属于这里**，它们属于 Script，之后进入分镜列表。

- 角色按可见状态分行；换装、受伤/血迹、伪装或摘除关键道具形成独立状态行。只给实际要生成角色锚点的人物分配 `char_*` 资产 ID；一次性、非关键且无需跨镜身份连续的轿夫、仆从、路人等保留在分镜和 prompt 文字中。稳定群演需要跨镜一致时才保留一个代表性锚点。
- 多角度、跨场复用或承担主要戏份的地点生成场景锚点；只出现一两镜的过场或闪回背景留在分镜和视频 prompt。
- 跨场复用且有特写、单场反复交互或承担剧情信物功能的道具生成主卡，并写清持有、交接、摘除、掉落或损毁的生命周期。每条资产标注本集来源，不混入 `target_episode_scope` 外内容。

## 按模式选择音频策略

生产模式决定台词如何进入画面。把选择记录在音频策略锁项中，Visual Gen work items 通过 `audio_approach` 字段继承它。

- **Mode A（真人实拍）**让对白和表演绑定在一起：说话随视频一起生成，让口型、表情和声音保持同步。台词走原生视频音轨；独立对白配音只用于真正的画外旁白，不用于屏幕内角色说话。
- **Mode B（漫画/动画）**使用视频生成时的原生音频承载台词和环境声，不生成独立后期 TTS。
- 生成片段不烘焙 BGM。`bgm_policy=不生成` 时 Post 不生成、不混入 BGM；`bgm_policy=用户提供` 时只使用用户提供的音轨和使用要求；`bgm_policy=生成` 时每集生成一条完整 BGM。BGM 的风格、乐器和情绪结构必须同时依据剧本题材、时代地域、世界观和本集分镜情绪曲线确定，最终由 Post 混入。该锁项一经用户选择，下游不得覆盖。

## 从来源剧本工作

- 现有剧本是事实源：只提取，不自行扩写。若剧本包含多集，只规划已确认的 `target_episode_scope`。
- 不要新增调性、剧情、角色立场、旁白或镜头风格，除非用户提供或确认过。
- 编写资产清单时，根据对白和动作识别时长体量，但不在资产阶段设定或反推目标秒数；分镜列表阶段按 `storyboard.md` 的逐句时长账本得到实际时长，不要静默压缩对白。

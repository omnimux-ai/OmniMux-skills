# A+ 内容

A+ 内容不是把卖点排成图文长页，而是把用户购买前的疑问拆成一组可扫描、可信、能转化的内容模块。

它的核心交付是一套详情页内容架构：模块顺序、每个模块解决的购买疑问、标题/正文/对比文案、视觉方向、图片提示词和上线前检查。

This skill is a public business-methodology skill. Its user-facing contract is the planning guidance, copy structure, visual prompting rules, review criteria, and static support materials in this directory.

## 公开边界

- 只负责详情页/A+ 模块规划、模块文案、视觉方向、提示词包和交付检查。
- 不承诺直接生成最终图片、自动抓取商品链接内容、自动读取站外详情页或自动发布素材。
- 不把任何提示文件、模板文件或样例文件变成固定工作流、固定阶段机、强制工具顺序或完成门禁。
- 不负责主图矩阵、单张海报、信息图、视频分析、视频脚本或多角度标准拍法。

## 能力包结构

按任务需要读取根目录下的支持材料：

- `docs/usage.md`：如何用这套能力包完成 A+ 内容任务。
- `docs/input-output-spec.md`：输入结构、模块对象、提示词包和交接字段约定。
- `docs/compliance-notes.md`：详情页文案、对比表达、认证和视觉风险边界。
- `prompts/system.md`：总边界和任务切分原则。
- `prompts/analyzer.md`：如何把产品信息整理成购买疑问与证据清单。
- `prompts/planner.md`：模块顺序、模块职责和页面叙事安排。
- `prompts/writer.md`：标题、正文、对比文案和品牌故事写法。
- `prompts/generator.md`：把模块转成适合设计或生图交接的视觉提示。
- `schemas/*.schema.json`：结构化输入输出参考合同。
- `templates/*.md`：模块规划、风格说明、品牌故事和提示词包交付模板。
- `config/*.yaml`：静态偏好、布局建议、风格预设和风险约束。
- `examples/`：校准样例，不代表效果保证。

## 适用场景

- 用户要做 A+ 内容、品牌故事、商品详情页、亚马逊/独立站图文详情。
- 用户已有产品卖点，但不知道怎么拆成模块、标题、说明、对比和视觉提示词。
- 用户需要把产品信息变成一套可交付给设计师、AI 出图或运营上架的内容包。
- 用户要检查现有详情页是否信息重复、卖点空泛、证据不足、版式不利于转化。

## 不适用场景

- 用户只要单张海报、普通主图或 Listing 套图；优先用 `product-image-set` 或 `image-creation`。
- 用户只要产品正侧背俯等角度补齐；优先用 `multi-angle-product-image`。
- 用户只要结构化信息图、知识图或数据图；优先用 `infographic`。
- 用户只要视频脚本、分镜或视频提示词。
- 用户要求直接生成图片但没有先定义模块、卖点和文案层级。
- 用户要求执行本目录内脚本、批处理生成文件或调用未公开工具。

## 输入要求

- 产品名称、品类、核心卖点、目标人群和使用场景。
- 品牌调性、平台要求、竞品参考或视觉偏好。
- 可选：产品图片、参数、禁用表达、合规限制。

## 任务模式

| 模式 | 任务 |
| --- | --- |
| `content-architecture` | 规划模块顺序、每个模块承担的购买说服任务和信息密度。 |
| `copy-pack` | 输出标题、副标题、要点说明、对比文案和品牌故事段落。 |
| `visual-prompt-pack` | 把每个模块转成图片生成或设计执行提示词。 |
| `review` | 检查内容是否清晰、可信、平台适配、无夸大风险。 |

## 输出合同

1. **任务边界**：目标平台、目标用户、输入限制和关键假设。
2. **模块清单**：模块名、解决的购买疑问、核心信息、证据需求、推荐视觉。
3. **文案层级**：标题、副标题、要点、对比说明、品牌故事或 FAQ 文案。
4. **视觉交接**：构图方向、留白要求、素材依赖、负面元素和提示词包。
5. **风险与缺口**：需要补证的信息、合规提醒和上线前检查点。

## 质量检查

- 每个模块必须解决一个明确购买疑问。
- 卖点表达要能被图片或版式证明，不能只堆形容词。
- 模块之间要有递进关系，不能重复展示同一信息。
- 涉及功效、健康、收益、认证时必须标注证据需求。
- 不虚构认证、排名、销量、测评、before/after 结论或平台背书。

## 运行边界

- 本 skill 只提供上下文，不得强制 workflow、固定阶段机、provider 路由、工具选择或完成门禁。
- 是否调用工具取决于当前用户请求、输入完整度、权限和工具 schema。
- 如果输入缺失，只问会改变输出的最小澄清问题；否则声明假设并继续。
- 区分分析、创作、转换、变体规划和交付移交；不要在用户只要求分析时升级成生成任务。

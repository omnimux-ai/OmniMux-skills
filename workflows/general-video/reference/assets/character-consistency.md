# Character Consistency — 人物连续性

## Activate When

同一人物或角色会出现在多个镜头、状态或最终资产中，且现有参考不足以稳定身份时读取。一次性人物、用户允许每镜变化或既有 anchor 已足够时跳过。

## Decision Test

- 先确认需要保持的是同一身份、同一状态，还是同一身份的明确状态变化。
- 身份连续性优先锁定可见结构：脸部骨相与五官关系、发型、体型与轮廓、核心服装 / 装备、标志性特征。
- 表情、姿势、镜头、灯光和一次性动作不是身份事实；除非用户要求，不要把它们冻结。
- 持续换装、损伤或形态变化需要独立状态记录；短暂表演变化仍使用同一 anchor。
- 清晰关系 / 群像图可以指导 blocking 或作为调用级 supporting ref；当人物身份需要跨镜稳定时，它不能替代每个 persistent subject 的 core anchor。

## Action

### 图像与文字双锚点

复用共享 Asset Pipeline 规定的 character / subject anchor，并为每个持续状态提取一张紧凑 Lock Card：

| Field | Content |
|---|---|
| Identity | 角色名与当前状态 |
| Face | 脸型、五官关系、肤色等可见身份事实 |
| Hair | 发色、长度、轮廓与固定造型 |
| Body | 体型、比例与姿态习惯中真正稳定的部分 |
| Outfit | 当前持续服装 / 装备 |
| Signature | 痣、疤、纹样、配饰或轮廓性特征 |

- Lock Card 必须来自用户输入、参考证据或已批准文档，不能补写未经依据的审美细节。
- 每个持续人物 / 状态都要有稳定的图像 ref 和 Lock Card；每个 work item 用稳定 ref id 显式映射人物，只引用本镜头实际出现的角色。
- 多人物镜头保持每个身份独立，不把一个人的脸、服装或标记扩散给其他人物。
- 状态变体继承基础身份，只写持续变化；下一状态依赖当前有效状态时使用串行链。
- 基础人物资产使用中性表情、持续服装和统一背景；情绪、动作、镜头光线和临时污渍只作为当前 work item 的变化。
- Prompt 先写本镜头动作，再紧凑声明角色 ref 与必须保持的可见身份特征；不要重复整张角色档案，也不要只写“保持一致”而不绑定具体 ref。
- 多角色 prompt 明确写出 `Image N = 人物/状态` 的对应关系；不要把群像图当成所有人物的身份锚点。
- 用户要求跨媒介重绘时保留身份 / 设计结构，但让材质、比例细节和渲染方式适配目标媒介。

### 派单前核对

- 核对人物名、状态名、服装、发型、标志特征和 `refs` 顺序是否与 Lock Card 一致。
- 角色卡、用户上传图或 anchor 图是图像锚点；Lock Card 是文字锚点，两者必须指向同一人物和同一状态。
- 角色需要说话或近景时，确认下游同时拿到脸部近景 ref；只有 front / side / back 全身图时，记录脸部连续性风险。
- 不把 character sheet 当作视频 first frame；需要首帧时，先从角色锚点派生符合场景的首帧，再交给视频 work item。

## Review

检查人物是否仍可由脸部关系、轮廓、发型和标志特征识别；检查服装 / 损伤状态是否与 source range 一致；检查 ref 顺序、背景、皮肤和光线是否把人物身份带偏；检查多角色是否发生身份混合。局部问题只修受影响 work item，不重做已通过的其它人物或镜头。

## Boundary

- 是否需要 anchor、默认六视图结构、同批 vendor/model lock 和状态依赖，以共享 Asset Pipeline 为准。
- 多参考角色绑定与可见特征取舍，以 Semantic Judgment 和 character-refs failure card 为准。
- 本文件不规定固定模型、参考槽上限、私有素材注册、denoise 或重试次数。

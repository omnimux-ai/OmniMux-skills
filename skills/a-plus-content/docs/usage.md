# A+ 内容使用说明

本文件说明如何使用 A+ 内容 skill 包。它不是脚本手册，也不定义自动抓取、自动生图、自动发布或固定执行链路。

## 读取顺序

1. 先读根目录 `SKILL.md`，确认任务是否属于详情页/A+ 内容规划。
2. 需要完整任务边界时读 `prompts/system.md`。
3. 需要拆购买疑问和证据时读 `prompts/analyzer.md` 与 `config/constraints.yaml`。
4. 需要规划模块顺序时读 `prompts/planner.md` 与 `config/layouts.yaml`。
5. 需要写文案时读 `prompts/writer.md`。
6. 需要做视觉交接或提示词包时读 `prompts/generator.md` 与 `config/styles.yaml`。
7. 需要稳定字段时读 `docs/input-output-spec.md`、`schemas/*.schema.json` 和 `templates/*.md`。
8. 涉及认证、对比、健康功效、销量或品牌使用边界时读 `docs/compliance-notes.md`。

## 输入类型

Agent 可以处理以下用户已经提供的材料：

- 产品名称、类目、卖点、参数、品牌调性和目标平台。
- 商品图片、包装图、细节图、品牌视觉资产。
- 用户已有的详情页草稿、竞品参考、模块需求或禁用表达。
- 商品链接或参考页面作为线索，但不能把不可见页面内容当成已确认事实。

## 输出形态

默认输出一份面向运营、设计或内容团队的详情页内容包，包含：

- 页面目标与目标用户假设。
- 模块顺序和每个模块解决的购买疑问。
- 标题、副标题、正文要点、对比说明或品牌故事文案。
- 视觉方向、提示词、素材需求和留白要求。
- 风险清单、缺失信息和上线前检查点。

如果用户需要结构化结果，可参考 `schemas/plan.schema.json`、`schemas/prompt.schema.json` 和 `schemas/output.schema.json` 输出 JSON 形态。

## 运行边界

以下能力不属于本 skill 的公开运行资产：

- 自动抓取外部详情页并声称已读取全部内容
- 自动生成最终图片或直接执行出图工具
- 固定阶段机、隐藏工作流、强制 required-next tool
- 未经确认的竞品对比、认证、销量、健康功效和 before/after 结论

## 常见处理

### 用户只给商品链接

可以把链接当成补充线索，但不要假装已经读完页面。先基于用户已提供的信息继续，必要时提醒对方补商品图、参数或已有文案。

### 用户只给产品图

可以先做客观识别和可见信息整理，再输出模块框架与待补证据清单。不要从图片推断看不见的参数、认证或功能。

### 用户要直接生成图片

先完成模块规划、文案层级和提示词交接，再根据当前对话是否真的要求生图决定是否进入图片能力。不要把详情页规划直接升级成图片执行。

### 用户要求复盘现有详情页

先按模块检查信息是否重复、证据是否不足、视觉是否抢文案、对比是否过度，再给重排建议。不要把 review 结果写成未经验证的新事实。

# 多角度产品图使用指南

## 使用方式

1. 先读顶层 `SKILL.md`，确认任务属于多角度产品图规划或覆盖诊断。
2. 需要工作方法时读 `prompts/system.md`、`prompts/planner.md` 和 `prompts/angle-generator.md`。
3. 需要稳定字段时参考 `schemas/`。
4. 需要统一交付格式时参考 `templates/`。
5. 需要补充角度定义、命名或检查口径时参考 `assets/`。

## 快速工作流

1. 明确产品证据：参考图数量、已知角度、材质颜色、结构、尺寸、包装和品牌标识。
2. 判断可见性：哪些视角有证据，哪些视角只能谨慎推断，哪些必须补素材。
3. 定义角度矩阵：正面、三分之四、侧面、背面、顶部、底部、细节、包装和比例视图。
4. 写一致性规则：轮廓比例、接口位置、缝线、纹理、标识、包装、颜色和材质锁定。
5. 输出 prompt pack：每个角度的画面说明、构图、光线、背景、正向提示词和负向约束。
6. 做 coverage review：查角度遗漏、重复视角、不可见结构风险和生成漂移风险。

## 输出建议

- `参考证据摘要`：已有素材、可确认特征、缺失视角。
- `角度矩阵`：角度、展示目的、画面、必须保持一致的产品特征、所需素材。
- `Style Bible`：跨图统一背景、光线、比例、材质、颜色、标识和包装规则。
- `Prompt Pack`：每个角度的生成提示词和负向约束。
- `风险清单`：不可见结构、缺少证据、可能生成漂移、商标或宣传风险。

## 边界提醒

- 用户要完整 Listing 套图转化顺序时，优先使用 `product-image-set`。
- 用户只要单张参考图改版时，优先使用 `image-recreation`。
- 用户要求直接生成最终图片时，先产出可执行 prompt pack；是否调用图像工具由当前请求、权限和可见工具 schema 决定。
- 如果核心结果必须依赖代码执行、适配器或固定工作流，应改判为代码执行候选能力，而不是继续扩充当前能力包。

## 禁止事项

- 不把不可见产品结构写成确定事实。
- 不为缺少证据的认证、销量、功效、排名、奖项或用户反馈背书。
- 不复制受保护的品牌表达、标识、包装设计或平台信任元素。

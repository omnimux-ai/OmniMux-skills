# 语音批次组织（Speech Batching）

## Activate When

- 需要生成多句旁白、对白、角色台词或多语言版本。
- 需要在效率、角色一致性和局部重试之间取得平衡。

## Decision Test

只有彼此独立、共享同一说话人映射与表演方向、且任一句失败都能单独重做的条目，才适合放入同一批次。

## Batch Together When

- 句子属于同一语言、同一角色或稳定旁白身份。
- 音色、语速、情绪强度和录音空间要求一致。
- 条目之间没有必须连续演出的打断、重叠、接话或呼吸依赖。
- 每条都有稳定 id、原文、角色、顺序和下游用途。

## Keep Separate When

- 角色、语言、音色、参考声音或表演方向不同。
- 台词需要连续对戏、同步打断、情绪递进或精确衔接。
- 单条特别长、包含多段状态变化，或需要单独确认发音。
- 某条需要不同的后期、权限或交付格式。

## Apply

- 建立稳定的 speaker → voice/ref 映射，并在整个项目中复用；不要按批次顺序临时分配。
- 保留批准文本原样，批次只改变调度，不改变措辞、标点语义或角色归属。
- 每个结果回写到自己的逻辑 id；下游按 id 消费，不依赖返回数组位置猜测。
- 批次部分失败时只重做失败项，并复用原映射与表演方向。
- 需要跨句一致时记录紧凑的表演 capsule，例如距离、能量、情绪弧和发音词典。

## Boundaries

- 不为追求更少调用把所有角色、语言或章节塞进一个批次。
- 不把旧的请求数组结构、字段名或并发上限写进计划；以当前工具 schema 为准。
- 不让局部失败触发全部语音重生成。

## Check

- 角色音色与发音跨条目稳定，顺序可追溯。
- 任一条目都能独立试听、替换和重试。
- 拼接后没有因批次边界产生的语气重置或空间跳变。

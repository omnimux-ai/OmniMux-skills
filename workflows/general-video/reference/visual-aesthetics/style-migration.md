# 风格迁移（Style Migration）

## Activate When

- 用户要求参考某张图或视频的画风、视觉语言或质感，应用到新的主体、场景或动作。
- Reference Brief 需要区分哪些特征继承、哪些必须保持新内容身份。

## Decision Test

先给每份参考明确 role。只有被指定为 style 的参考才贡献风格；subject、world、layout、pacing 等角色分别处理，不能让一张参考自动控制全部维度。

## Decompose the Style

- **媒介与成像**：摄影、插画、拼贴、版画、低保真数字或混合媒介，以及可见的制作痕迹。
- **线条与形状**：轮廓是否存在、松紧、粗细、简化程度和形状语言。
- **细节密度**：人物、道具和背景分别保留多少信息，哪里刻意留白。
- **色彩结构**：主辅点颜色的职责、明度、饱和度和冷暖关系。
- **光与体积**：平面色块、柔和渐变、硬阴影、留白高光或其它塑形方式。
- **构图与空间**：主体位置、留白、背景复杂度、透视和视觉重心。
- **表面与节奏**：颗粒、笔触、纸张、噪点、重复图形，以及视频中的运动与变化速度。

## Preserve the New Content

- 单独写清新主体的身份、姿态、服装、场景和动作，不从风格参考偷换内容。
- 参考图中的人物、道具、文字和构图只有被对应 role 明确指定时才继承。
- 主体参考与风格参考冲突时，主体身份和用户内容优先；风格只改变呈现方式。
- 内部 contribution map 记录每份参考贡献与 ignore 边界；最终 prompt 只写正向贡献，并按输入顺序保持 refs 与描述一致。只有用户明确排除、policy block 或 vendor 硬约束才写显式限制。

## Apply

- 先写一条可执行的推荐迁移方向，不默认提供多种风格分支。
- 迭代时保留已成立的维度，只修正用户指出或结果证实漂移的维度。
- 用参考中可见证据描述，不猜测精确设备、材料配方或作者流程。

## Boundaries

- 不用单个风格标签替代拆解，也不强制复制整段 prompt preset。
- 不复制参考主体、logo、文字或独特布局来冒充“同风格”。
- 不因生成更容易而改变用户指定的身份、事件或叙事关系。
- 本卡不自动增加风格确认 gate；只有真实互斥方向仍未解决时才提问。

## Check

- 遮住新主体后，仍能从线条、色彩、光线、空间和质感看出风格关联。
- 遮住风格后，新主体身份和用户要求仍完整准确。
- 迁移后的每个特征都能追溯到参考证据或明确的创作决定。

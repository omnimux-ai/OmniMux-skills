# 多角度产品图预览联系表说明

> 用途：用于整理一组多角度产品图的缩略预览、角度标识、命名映射、选片沟通与验收记录
> 适用：AI生图结果预览、摄影选片、修图对稿、团队内部审核、客户确认、资产归档

## 一、什么是预览联系表

预览联系表，通常指将一组产品图按统一顺序排版为可快速浏览的缩略图清单，并附带：

- 视角名称
- 文件名
- 用途说明
- 备注
- 选中状态
- 修订状态

它的核心作用不是替代原图，而是帮助团队在一页或少数几页里快速完成以下工作：

- 看全一组图
- 判断角度是否齐全
- 判断结构和风格是否一致
- 标记要保留、重做、修图或替换的图
- 建立“缩略图视角”与“正式文件名”之间的对应关系

## 二、预览联系表的核心目标

### 主要目标
- 让一组多角度产品图一眼看全
- 帮助快速发现缺角、重复角度和一致性问题
- 为选片、修图和交付提供统一沟通载体
- 降低团队在文件夹内逐张打开查看的成本

### 次要目标
- 提升项目管理效率
- 形成可存档的审核记录
- 作为客户确认或跨部门沟通材料
- 帮助后续生成最终交付清单

## 三、适用场景

预览联系表尤其适合以下场景：

- 一次生成/拍摄了多张不同角度图
- 需要从多个候选图中选出正式交付版本
- 需要标记哪些图用于主图、详情页、A+或广告
- 需要多人协作审核
- 需要留痕记录“哪个版本被确认”
- 需要核对命名是否与视角一致

## 四、推荐包含的信息字段

一份标准的预览联系表，建议至少包含以下字段：

| 字段 | 说明 |
|---|---|
| 序号 | 图像顺序编号，方便沟通 |
| 缩略图 | 该图的小预览 |
| 视角 | 如正面、前三分之四、左侧面等 |
| 文件名 | 对应正式文件名 |
| 用途 | 主图、详情页、A+、广告、包装等 |
| 状态 | 待审核、通过、重做、待修图 |
| 备注 | 问题说明或修改要求 |

可选字段：
- 比例
- 背景类型
- 版本号
- 负责人
- 审核日期
- 最终选中标记

## 五、推荐排版顺序

建议预览联系表按“用户理解产品的逻辑顺序”排版，而不是按生成时间顺序。

### 推荐基础顺序
1. 正面
2. 前三分之四
3. 左侧面
4. 右侧面
5. 背面
6. 顶部
7. 底部
8. 微距细节 1
9. 微距细节 2
10. 包装图

### 这样排序的好处
- 先看整体识别
- 再看立体感
- 再看侧边、背面、顶部和底部
- 最后看品质细节和包装
- 更方便快速判断信息是否完整

适合客户确认、轻量选片、视觉展示

每张卡片可包含：
- 缩略图
- 视角名
- 文件名
- 选择框
- 备注区

### 方案 C：分组型
适合图量较大时按功能分组

分组建议：
- 核心展示：正面、前三分之四、背面
- 结构说明：左侧、右侧、顶部、底部
- 品质卖点：细节 1、细节 2
- 交付信息：包装图

## 七、状态标签建议

建议统一使用以下状态标签，避免沟通混乱：

- 待审核
- 已通过
- 待修图
- 待重做
- 待确认
- 已选中
- 不采用

### 状态含义建议
- 待审核：还未正式查看
- 已通过：可进入交付
- 待修图：结构可用，但需后期微调
- 待重做：角度、结构或质感不合格
- 待确认：需团队或客户最终决定
- 已选中：作为正式版本保留
- 不采用：不进入最终交付

## 八、备注字段建议写法

备注应尽量具体，避免模糊表达。

### 推荐写法
- “正面结构正确，可作为基准图”
- “前三分之四立体感好，建议作为主图候选”
- “左侧厚度略薄，需回调比例”
- “背面Logo位置不稳定，建议重做”
- “顶部按钮细节清晰，可保留”
- “微距图材质自然，适合详情页卖点”
- “包装图配件数量需再核对”

### 不推荐写法
- “一般”
- “还行”
- “不太对”
- “看下”
- “有点问题”

原因：
- 不利于后续执行
- 无法形成清晰修改指令
- 多人协作时容易产生理解偏差

## 九、联系表中的常见审核维度

建议在查看联系表时按以下维度快速扫描：

### 1. 角度完整性
- 是否覆盖正面
- 是否覆盖前三分之四
- 是否覆盖侧面
- 是否覆盖背面
- 是否覆盖顶部或底部
- 是否有至少一张细节图
- 如有需求，是否有包装图

### 2. 一致性
- 是否看起来是同一款产品
- 颜色是否统一
- 材质是否统一
- Logo是否统一
- 轮廓比例是否统一
- 光线风格是否统一

### 3. 商业可用性
- 是否有主图候选
- 是否有详情页结构说明图
- 是否有卖点细节图
- 是否有包装说明图
- 是否满足平台展示需求

### 4. 文件管理准确性
- 文件名是否与视角匹配
- 版本号是否统一
- 是否有重复命名
- 是否有漏命名或错命名

## 十、预览联系表常见问题

### 1. 缩略图顺序混乱
表现：
- 无法按逻辑看全产品
- 相同功能图被打散
- 选片效率低

解决：
- 固定统一排序规则
- 先整体后局部
- 先识别后结构后细节后包装

### 2. 命名与视角不一致
表现：
- front 文件其实是 45 度图
- left / right 标错
- detail 图命名无法分辨内容

解决：
- 联系表中强制同时显示“视角名 + 文件名”
- 审核阶段同步修正命名

### 3. 缺少状态字段
表现：
- 看完不知道哪些图可用
- 团队之间重复讨论同一问题

解决：
- 每张图必须有状态
- 审核后即时更新

### 4. 备注不具体
表现：
- 执行端不知道怎么改
- 客户和设计理解不同

解决：
- 备注写具体问题和修改方向
- 例如说明“厚度偏薄”“Logo偏大”“底部支撑不清晰”

### 5. 缩略图太小或太密
表现：
- 看不清细节
- 容易误判

解决：
- 标准角度图与微距图可适当区别尺寸
- 必要时分两页：整体角度一页，细节与包装一页

## 十一、推荐审核流程

### 第一步：看完整性
先看是否缺角、重复角度或少必要图

### 第二步：看一致性
确认不同图是否属于同一产品

### 第三步：选主图候选
优先从前三分之四图或正面图中选

### 第四步：选详情页说明图
选择侧面、背面、顶部、底部、包装图

### 第五步：选卖点图
选择最能证明材质和工艺的微距图

### 第六步：更新状态
将每一张图标记为通过、待修图、重做或不采用

## 十三、最终建议

预览联系表的价值，不在于“把缩略图排在一起”，而在于建立一套低成本、高效率、可留痕的审核系统。
一份好的联系表应同时解决四件事：

- 看全
- 看懂
- 选出
- 改对

因此，建议在每次多角度产品图任务中，都将预览联系表作为正式交付流程的一部分，而不是临时整理的附属文件。
